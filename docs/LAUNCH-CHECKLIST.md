- [ ] ฐานข้อมูล 2 role (เจ้าของตาราง + role ของแอปที่ Row-Level Security บังคับ) ตรวจว่าร้านหนึ่งเห็นข้อมูลอีกร้านไม่ได้บน server จริง

- [ ] สำรองข้อมูลอัตโนมัติ + กู้ย้อนเวลา (PITR) และ**ซ้อมกู้คืนจริงหนึ่งรอบ** จดขั้นตอนไว้ให้คนอื่นทำตามได้
- [ ] แจ้งเตือนเมื่อระบบมีปัญหา: ตรวจว่าเว็บยังเปิดได้, เก็บ error ของ server และเบราว์เซอร์, ส่งแจ้งเตือนถึงคนดูแล
- [ ] ตารางเวลางานเบื้องหลัง: ลบข้อมูลร้านที่เลิกใช้ครบกำหนด (`tools/retention.mjs`), ลบไฟล์ที่ไม่มีข้อมูลอ้างถึง
- [ ] ทดสอบรับโหลดขนาดอู่นำร่อง (หลายเครื่องในอู่บันทึกพร้อมกัน) ด้วย k6
- [ ] ตรวจความปลอดภัยรอบสุดท้ายก่อนเปิด (การเข้าระบบ ค่าลับของ server header ของเว็บ)

## ด่าน 2: อู่นำร่อง (ข้อมูลจริง)

- [ ] **ผู้ทำบัญชีตรวจ** (รายการละเอียดใน NOTES.md ข้อ "ให้ผู้ทำบัญชีดู" ของแต่ละงาน):
  ใบกำกับที่ออกแทน ปิดงวดภาษี และใบลดหนี้ (T1, T2, T6, T7) · แบบ 50 ทวิ ทั้งของผู้ขายและพนักงาน · VAT ของค่าธรรมเนียมบัตร (F3) ·
  บัญชีของสินค้าขาด/ของเกิน (6190 / 4030) · ฐานประกันสังคมเดือนที่ทำงานไม่เต็ม และยอดค้างจ่ายในงบทดลอง · ภ.ง.ด.1 นับตามวันที่จ่าย ·
  วิธีคำนวณภาษีเงินเดือน (F6-ก ตอนนี้ร้านกรอกเอง) · สินทรัพย์ทั้งหมดของงาน 3.13 · การเก็บประวัติ 5 ปีหลังร้านเลิกใช้ (15.6)

  สัญญาประมวลผลข้อมูลระหว่าง DriveGo กับอู่ เพราะอู่เป็นเจ้าของข้อมูลลูกค้าและพนักงานของตัวเอง)

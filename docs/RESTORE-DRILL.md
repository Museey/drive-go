# ซ้อมกู้ข้อมูลคืน (server ทดสอบ)

LAUNCH-CHECKLIST ด่าน 1 "สำรองข้อมูลอัตโนมัติ + กู้ย้อนเวลา (PITR) และ**ซ้อมกู้คืนจริงหนึ่งรอบ** จดขั้นตอนไว้ให้คนอื่นทำตามได้"

## DigitalOcean สำรองอะไรให้ (คู่มือ DigitalOcean ฉบับ ก.ค.–ส.ค. 2026)

- **สำรองทั้งฐานข้อมูลทุกวันอัตโนมัติ เก็บ 7 วัน** ไม่ต้องตั้งอะไร ไม่ทำให้ระบบช้า
- **กู้ย้อนไปจุดเวลาไหนก็ได้ภายใน 7 วัน** (point-in-time) ละเอียดถึงนาที
- **การกู้ไม่เขียนทับของเดิม**:
  - DigitalOcean สร้าง**ฐานข้อมูลชุดใหม่** ที่มีข้อมูล ณ เวลานั้น
  - เราต้องย้ายแอปไปใช้ชุดใหม่เอง
  - ชุดใหม่คิดเงินแยกจนกว่าจะลบ
- **ลบฐานข้อมูลชุดไหน การสำรองของชุดนั้นหายไปด้วย**

## เมื่อไรใช้อะไร

| เหตุ | ใช้ |
|---|---|
| ร้านหนึ่งลบหรือแก้ข้อมูลผิด (ทั้งร้าน) | ปุ่มในโปรแกรม: เมนู 10 → จุดสำรอง → กู้คืน (จุดสำรองรายวันของร้าน และสำเนาก่อนล้าง/กู้คืน/นำเข้า เก็บ 90 วัน) ร้านทำเองได้ ไม่กระทบร้านอื่น |
| ฐานข้อมูลเสียหายทั้งก้อน, ข้อมูลหลายร้านหาย, คำสั่งผิดของทีมงาน | **กู้ทั้งฐานข้อมูล** ตามคู่มือนี้ ข้อมูลทุกร้านย้อนไปจุดเวลาที่เลือก ที่บันทึกหลังจากนั้นหาย |

## เครื่องมือตรวจ: `node tools/restore-check.mjs`

- พิมพ์จำนวนข้อมูลของแต่ละร้านและ "ลายนิ้วมือ" ไว้เทียบฐานข้อมูลสองชุด
  - ข้อมูลเท่ากัน → ลายนิ้วมือตรงกัน
  - ไม่พิมพ์ข้อมูลของร้านหรือรหัสใด ๆ ส่งผลให้ Claude ดูได้
- `--marker ข้อความ`: บอกว่าข้อความนี้อยู่ในร้านไหน ใช้หา "ลูกค้าที่ใช้ซ้อม"
- **รันที่ไหน**: แอป **drivego-test** → แท็บ **Console** → ส่วนประกอบ **web**
  - พิมพ์คำสั่ง แล้ววางข้อความเชื่อมต่อของ **doadmin** เมื่อถูกถาม
  - ข้อความเชื่อมต่อไม่แสดงบนจอ และไม่ถูกจำในประวัติคำสั่ง
  - ข้อความเชื่อมต่อนี้ใส่ได้เฉพาะใน DigitalOcean **ห้ามส่งในแชต**
- ต้องรันใน Console ของแอป เพราะ:
  - ฐานข้อมูลรับเฉพาะแอป (Trusted sources)
  - ใบรับรองของฐานข้อมูลอยู่ในแอปแล้ว

## ขั้นตอนซ้อม (ราว 45–60 นาที)

ซ้อมโดย "ทำข้อมูลหาย" จริงหนึ่งอย่าง แล้วกู้กลับมาจนแอปใช้ข้อมูลที่กู้มา จดเวลาทุกขั้นเป็นเวลาไทย

**ก. ทำเครื่องหมายไว้ (5 นาที)**
1. เข้า `/demo-biz/` (dg1688 / 123456) → เมนู 02 ข้อมูลลูกค้า → เพิ่มลูกค้าใหม่ ชื่อ **ซ้อมกู้คืน** → บันทึก จดเวลา (**T1**)
2. Console ของแอป (web) พิมพ์ `node tools/restore-check.mjs --marker ซ้อมกู้คืน` แล้ววางข้อความเชื่อมต่อของ doadmin
   - ผลต้องบอกว่าพบ "ซ้อมกู้คืน" ใน demo-biz
   - คัดลอกผลทั้งหมดเก็บไว้ (ผล "ก่อน")

**ข. ทำข้อมูลหาย (3 นาที)**

3. รออย่างน้อย **3 นาที** หลัง T1 แล้วลบลูกค้า **ซ้อมกู้คืน** ในโปรแกรม จดเวลา (**T2**)
4. รันคำสั่งเดิมใน Console: ต้องบอกว่า "ไม่พบ"

**ค. กู้ฐานข้อมูลไปจุดก่อนลบ (10–20 นาที รอ DigitalOcean)**

5. **Databases** → **drivego-test-db** → หน้า **Overview** → เมนู **Actions** → **Restore from backup**
   - ถ้าเลือกไม่ได้หรือบอกว่ายังไม่มี backup: ฐานข้อมูลที่เพิ่งสร้างอาจต้องรอ backup แรก (ไม่เกิน 1 วัน) แล้วเริ่มใหม่ในวันถัดไป
   - ถ้าบอกว่าเกินจำนวนฐานข้อมูลที่บัญชีมีได้: ติดต่อ support ของ DigitalOcean
6. เลือก **point in time** = ระหว่าง T1 กับ T2 เช่น T1 + 1 นาที
   - ระวังเขตเวลา: ถ้าหน้าจอเป็น UTC ให้ลบ 7 ชั่วโมงจากเวลาไทย
7. ชื่อ **drivego-test-db2** → **Restore to New Cluster** → รอจนเป็นสีเขียว จดเวลา (**T3**)

**ง. ย้ายแอปไปใช้ฐานข้อมูลที่กู้มา (15–20 นาที)**

8. ฐานข้อมูลใหม่ **drivego-test-db2**:
   - **Users & Databases**: ต้องมี user **drivego_app** (มากับข้อมูล) ถ้าไม่มี ให้เพิ่ม
   - **Network Access** → Trusted sources: เพิ่มแอป **drivego-test**
9. แอป → **Settings** → **App Spec** → **Edit** → บรรทัด `cluster_name: drivego-test-db` เปลี่ยนเป็น `cluster_name: drivego-test-db2` → **Save**
10. ข้อความเชื่อมต่อของ **doadmin** ของ **drivego-test-db2** (Connection Details: Public network, doadmin, defaultdb, Connection string):
    ใส่แทน `MIGRATE_DATABASE_URL` เดิมของ **migrate**, **nightly**, **watch** (Run time, Encrypt) → Save
11. **Actions** → **Force rebuild and deploy** → รอเขียว จดเวลา (**T4**)

**จ. ตรวจ (5 นาที)**

12. เข้า `/demo-biz/` → ข้อมูลลูกค้า: **ลูกค้า "ซ้อมกู้คืน" กลับมา**
13. Console (web) รัน `node tools/restore-check.mjs --marker ซ้อมกู้คืน` อีกครั้ง
    - วางข้อความเชื่อมต่อของ drivego-test-db2
    - ต้องพบ "ซ้อมกู้คืน" และตัวเลขของทุกร้านตรงกับผล "ก่อน" (ข้อ 2)
    - ถ้ามีคนใช้ร้านตัวอย่างระหว่างนั้น ร้านนั้นอาจต่างได้
14. ส่งผลข้อ 2 และข้อ 13 ให้ Claude พร้อมเวลา T1–T4 (ไม่มีรหัสในผล)

**ฉ. เก็บกวาด**

15. เก็บ **drivego-test-db2** เป็นฐานข้อมูลหลักของ server ทดสอบ (Claude แก้ `.do/app.yaml` และคู่มือให้ชื่อตรง)
    แล้วลบ **drivego-test-db** เดิมหลังแน่ใจแล้วว่าใช้ได้: **Actions** → **Destroy** (คิดเงินสองชุดจนกว่าจะลบ)

## ตัวเลขที่ได้จากการซ้อม

- **เวลาที่ระบบกลับมา (RTO)** = T4 − เวลาที่เริ่มข้อ 5 บอกว่าถ้าฐานข้อมูลเสียจริง อู่ใช้งานไม่ได้นานเท่าไร
- **ข้อมูลที่หาย (RPO)** = ทุกอย่างที่บันทึกหลังจุดเวลาที่เลือก
  - ตอนเกิดเรื่องจริง ให้เลือกเวลาล่าสุดก่อนเกิดเหตุ ข้อมูลจะหายไม่กี่นาที
- ทั้งสองตัวเลขใช้ตัดสินเรื่องฐานข้อมูลสำรอง (HA) ของ server ใช้จริง (LAUNCH-CHECKLIST ด่าน 2)
  - HA ช่วยกรณีเครื่องเสีย (สลับเองในไม่กี่วินาที) ไม่ช่วยกรณีข้อมูลถูกลบผิด ซึ่งต้องกู้ตามคู่มือนี้

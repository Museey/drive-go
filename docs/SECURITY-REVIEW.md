# ตรวจความปลอดภัยก่อนเปิดใช้ (2026-10-31)

LAUNCH-CHECKLIST ด่าน 1 "ตรวจความปลอดภัยรอบสุดท้ายก่อนเปิด (การเข้าระบบ ค่าลับของ server header ของเว็บ)"
ตรวจจากโค้ดและลองกับระบบที่รันจริงในเครื่อง (`next start` + PostgreSQL) ยังไม่ได้ลองบน server จริง (รอ URL ของ DigitalOcean)

## header ที่เพิ่ม (ทุกคำตอบ)

| header | ค่า | กันอะไร |
|---|---|---|
| `Strict-Transport-Security` | `max-age=31536000` | เบราว์เซอร์ใช้ HTTPS เสมอ |
| `X-Content-Type-Options` | `nosniff` | เบราว์เซอร์เดาชนิดไฟล์เป็นสคริปต์ |
| `X-Frame-Options` / CSP `frame-ancestors` | `SAMEORIGIN` / `'self'` | เว็บอื่นฝังหน้าจอไว้หลอกให้กด (หน้าของแอปเองยังฝังไฟล์ PDF ได้) |
| `Content-Security-Policy` | `frame-ancestors 'self'; base-uri 'self'; object-src 'none'; form-action 'self'` | ฝังหน้า, `<base>` ปลอม, plugin, ฟอร์มส่งออกนอก (ยกเว้น `/api/files/` ซึ่งมี policy ของตัวเอง) |
| `Referrer-Policy` | `same-origin` | ส่งที่อยู่หน้า (มีรหัสร้าน) ให้เว็บอื่น |
| `Permissions-Policy` | ปิดกล้อง ไมค์ ตำแหน่ง การจ่ายเงิน USB | โปรแกรมไม่ใช้ |

CSP ยังไม่จำกัดสคริปต์และการเชื่อมต่อ: หน้าจอเดิมใช้สคริปต์ในหน้าและ `onclick` ทั่วไป และ ProX ออนไลน์ต่อ server ของเครือจากเบราว์เซอร์โดยตรง
(ข้อเสนอ 4)

## ข้อเสนอที่ต้องให้เจ้าของโปรเจกต์ตัดสิน

1. **จำกัดการลองเข้าระบบต่อเครื่อง (IP)**: ตอนนี้ล็อกเฉพาะบัญชีที่ผิด 5 ครั้ง คนเดียวลองหลายบัญชีหลายร้านได้ไม่จำกัด (และการตรวจรหัสแต่ละครั้งใช้เครื่อง server)
   เสนอ: เครื่องเดียวลองผิดเกิน 30 ครั้งใน 15 นาที ให้รอ 15 นาที โดยใช้ข้อความล็อกเดิมของระบบ (ไม่มีข้อความใหม่) — เปลี่ยนพฤติกรรม ต้องอนุมัติ
2. **ความยาวรหัสผ่านขั้นต่ำ**: ระบบเดิมรับรหัสผ่านสั้นเท่าไรก็ได้ (ตัวอย่างใช้ `1234`) เสนอ: รหัสที่ตั้งใหม่อย่างน้อย 8 ตัว (รหัสเดิมยังใช้ได้)
   ต้องมีข้อความใหม่ตอนตั้งรหัสสั้นเกิน — ต้องอนุมัติ
3. **ร้านตัวอย่างบน server ที่มีร้านจริง**: server ทดสอบเปิดร้านตัวอย่างที่รหัสผ่านเขียนอยู่ในคู่มือ (ใครก็เข้าได้ ข้อมูลแยกจากร้านอื่นด้วย RLS แต่เป็นทางให้คนนอกลองระบบได้)
   เสนอ: ก่อนเปิดอู่นำร่องบน server เดียวกัน ปิดการเปิดร้านตัวอย่าง (`SEED_DEMO_SHOPS`) และปิดร้านตัวอย่าง (`shop-admin close`) หรือแยก server ใช้จริงจาก server ทดสอบ
4. **XSS ในหน้าจอเดิม**: ลองแล้วไม่พบ แต่ `esc()` ไม่แปลง `'` และมี `innerHTML` 601 จุด ข้อความในปุ่มที่ใส่ชื่อลงใน `onclick` ยังเสี่ยง
   เสนอ (หลังเปิดนำร่อง ไม่บล็อก): ให้ `esc()` แปลง `'` ด้วย (เปลี่ยน frontend ต้องผ่านเฉลยทั้งหมด) และลอง CSP แบบ Report-Only ที่จำกัดสคริปต์เพื่อดูว่าหน้าจอใดพัง

## ต้องตรวจบน server จริงเมื่อได้ URL

- header ข้างบนออกมาจริงผ่าน load balancer ของ DigitalOcean และ http เปลี่ยนเป็น https เอง (`curl -sI`)
- ฐานข้อมูลรับเฉพาะแอป (Trusted sources ตามคู่มือส่วนที่ 3 ข้อ 5) และต่อด้วย TLS
- `/api/test-error` ตอบ 404, `/api/public/<รหัสร้าน>/dgb.v22` ไม่มีข้อมูลส่วนตัว
- ลองเข้าผิด 5 ครั้งถูกล็อก, cookie มี `Secure`

## 1) เลขที่เอกสาร

### R1 · เลขที่เอกสารออกตอนไหน และเลขของสาขาแฟรนไชส์

**ระบบเดิม:** ฟอร์มใบตัดสต็อกใบใหม่แสดงเลขถัดไปตั้งแต่ยังไม่บันทึก (S17 เห็น MA-SA261000015 ก่อนกดบันทึก) ส่วนใบเสนอราคาแสดง "(ยังไม่บันทึก)"
และใบกำกับภาษีแสดง "ออกเลขอัตโนมัติเมื่อบันทึก" (S10, S14) ตัวนับขยับตอนบันทึกเท่านั้น ปิดฟอร์มโดยไม่บันทึกไม่เสียเลข
เมื่อเลขออกที่ server ถ้าสองเครื่องเปิดฟอร์มพร้อมกัน ทั้งคู่จะเห็นเลขเดียวกัน แต่คนที่บันทึกทีหลังจะได้เลขถัดไป
อีกเรื่อง: ข้อมูลของแต่ละสาขาแฟรนไชส์ใช้ "สาขาหลัก" รหัส MA เหมือนกัน (ตัวนับของ B001 เป็น MA-SA2610, MA-TX2610 …) สาขา B001 และ B002 จึงออกเลข MA-SA261000001 ซ้ำกันได้
ในเครือเดียวกัน (ข้อ A7 ตัดสินให้เลขมีรหัสสาขาแล้ว แต่ยังไม่ได้ตัดสินว่าใช้รหัสไหน)

**ทางเลือก (ก) ตอนออกเลข:**
- ก) แสดงเลขที่คาดว่าจะได้เหมือนเดิม ถ้ามีคนบันทึกตัดหน้า เอกสารจะได้เลขถัดไป และข้อความบันทึกสำเร็จบอกเลขจริง
- ข) ทุกฟอร์มแสดง "ออกเลขอัตโนมัติเมื่อบันทึก" แบบใบกำกับภาษี
- ค) จองเลขตั้งแต่เปิดฟอร์ม (เลขไม่เปลี่ยน แต่ฟอร์มที่ไม่บันทึกทำให้เลขขาดช่วง ซึ่งเจ้าหน้าที่สรรพากรมักถาม)

**ทางเลือก (ข) รหัสสาขาแฟรนไชส์ในเลขที่:**
- ก) ใช้รหัสสาขาที่มีอยู่แล้ว เช่น B001-SA261000001
- ข) HQ ตั้งรหัสสั้น 2–3 ตัวอักษรให้แต่ละสาขาตอนเพิ่มสาขา (เช่น RS-SA261000001) แก้ไม่ได้หลังตั้ง
- ค) คงเลข MA ทุกสาขา (เลขซ้ำข้ามสาขาได้ ใช้ได้เฉพาะเมื่อทุกสาขาเป็นนิติบุคคลแยกกันและไม่ต้องดูรวมกัน)

**แนะนำ:** (ก) = ก หน้าจอเหมือนเดิมและเลขไม่ขาดช่วง · (ข) = ก ไม่ต้องตั้งรหัสใหม่ และ HQ เห็นอยู่แล้ว
**รอคำตอบนี้:** PR ออกเลขที่เอกสารที่ server (งานแรกของเฟส 3)

### R2 · ใบเสร็จรับเงิน (MA-RE) ออกเลขเมื่อไร

**ระบบเดิม:** รับเงินสองทางได้ผลต่างกัน (ข้อ 22 ที่อนุมัติให้แก้แล้ว แต่ยังไม่ได้เลือกว่าแก้ไปทางไหน):
รับผ่าน "หน้ารับชำระ" ของใบตัดสต็อก **ไม่ออกเลขใบเสร็จ** (S01 เงินสด, S20 โอนบางส่วน, S26 บัตร)
ส่วนรับผ่าน "ป๊อปอัพรับชำระเงินลูกหนี้" (เมนู 08, ใบวางบิล, บิลเงินเชื่อ) **ออกเลข MA-RE ทันที** (S21, S22, S25)
ปุ่ม "รับชำระ" บนหน้าแรกเปิดหน้าไหนขึ้นกับว่าเป็นบิลเงินเชื่อหรือไม่ (S22 ได้เลข, S26 ไม่ได้)
และยังสร้างใบเสร็จภายหลังจากหน้า 4.3 ได้ (S13 ลงวันที่ตามวันรับเงิน)

**ทางเลือก:**
- ก) ทุกครั้งที่รับเงิน (รวมรับบางส่วน) ออกเลขใบเสร็จอัตโนมัติ ทั้งสองทาง
- ข) ไม่ออกอัตโนมัติ ให้กดสร้างที่ 4.3 เมื่อลูกค้าต้องการ ทั้งสองทาง
- ค) ตอนรับเงินมีช่องติ๊ก "ออกใบเสร็จ" (ติ๊กไว้ก่อน) ทั้งสองทาง

**แนะนำ:** ก — เงินทุกบาทที่รับมีเลขเอกสารคุม ตรวจย้อนได้ว่าใครรับเงินสดเท่าไร
**รอคำตอบนี้:** PR ออกเลขที่เอกสารที่ server, PR รับชำระ

### R3 · ปุ่มล้างข้อมูล กู้คืนจุดสำรอง และนำเข้าไฟล์สำรอง เมื่อร้านใช้งานจริง

**ระบบเดิม:** "ล้างข้อมูลทั้งหมด" ลบเอกสารทุกหมวดและรีเซ็ตตัวนับเลขที่ (S74), "กู้คืนจากจุดสำรอง" และ "กู้คืนจากไฟล์สำรอง"
แทนที่ข้อมูลทั้งร้านด้วยของเก่า (S74, S100, S75) ข้อ A6 (เอกสารบัญชีห้ามลบ) และ A7 (ตัวนับห้ามรีเซ็ต) ตัดสินแล้ว
แต่ปุ่มทั้งสามยังทำให้ใบกำกับภาษีที่ให้ลูกค้าไปแล้วหายจากระบบได้ ถ้าเลขออกที่ server แล้วกู้คืนข้อมูลเก่า เลขเดิมก็ยังไม่ถูกใช้ซ้ำ แต่เอกสารหลังจุดสำรองจะหาย

**ทางเลือก:**
- ก) ร้านกดเองไม่ได้ ทีมงาน DriveGo ทำให้เมื่อร้านขอ (มีบันทึกว่าใครขอ ทำเมื่อไร)
- ข) เจ้าของร้านกดเองได้เฉพาะช่วงตั้งค่าร้าน (ก่อนออกเอกสารบัญชีใบแรก) หลังจากนั้นเป็นแบบ ก
- ค) กดได้ตลอดเหมือนเดิม แค่ตัวนับเลขไม่ย้อนกลับ

**แนะนำ:** ข — ช่วงทดลองตั้งค่ายังล้างได้สะดวก แต่เมื่อมีเอกสารภาษีแล้วข้อมูลหายเองไม่ได้
**รอคำตอบนี้:** PR ออกเลขที่เอกสารที่ server (ตัวนับ) และก่อนเปิดอู่นำร่อง

## 2) ภาษี

### R4 · การคิด VAT (ยืนยันตามระบบเดิม + 1 คำถาม)

**จะทำตามระบบเดิม:** ราคาขายเป็นราคาก่อน VAT, VAT 7% คิดจากยอดรวมทั้งใบหลังหักส่วนลดท้ายบิล ไม่คิดรายบรรทัด
(S10: 4,160.00 → VAT 291.20 → 4,451.20), ร้านที่ไม่จด VAT ระบบตั้ง VAT เป็น 0 และออกใบกำกับภาษีไม่ได้,
ปุ่ม "พิมพ์เอกสารอย่างย่อ" ของใบตัดสต็อกที่มี VAT พิมพ์หัวว่า "ใบกำกับภาษีอย่างย่อ / ใบตัดสต็อกขายสินค้า"
และใบที่ยังไม่มีใบกำกับเต็มรูปอยู่ในรายงานภาษีขายด้วยเลขใบตัดสต็อก (เช่น MA-SA261000001)
**สิ่งที่จะแก้ (ไม่ต้องตอบ ถ้าไม่ค้าน):** เก็บยอด VAT ของแต่ละใบเป็นทศนิยม 2 ตำแหน่ง ปัดครึ่งขึ้น (เดิมเก็บไม่ปัด แล้วปัดตอนแสดง),
ใบกำกับภาษีเก็บยอดของตัวเองตอนออก (เดิมคำนวณใหม่จากใบตัดสต็อกทุกครั้ง ข้อ 7), อัตรา VAT เก็บเป็นตารางกลางตามวันที่มีผล (เดิมเขียนตายตัว 7)

**คำถาม:** ร้านที่จด VAT ยังเลือก "ไม่คิด VAT" ได้รายใบ ทั้งใบเสนอราคา (VAT 7% (แยกนอก) / ไม่คิด VAT) และใบตัดสต็อก (ไม่มี / 7%)
- ก) ร้านที่จด VAT ล็อกเป็น 7% ทุกใบ
- ข) เลือกไม่คิด VAT ได้เฉพาะเจ้าของหรือผู้มีสิทธิ์ และต้องใส่เหตุผล (ลง audit)
- ค) ทุกคนเลือกได้เหมือนเดิม

**แนะนำ:** ข — กันพนักงานขายไม่คิด VAT เอง แต่ยังรองรับกรณีพิเศษ
**รอคำตอบนี้:** PR ภาษี (VAT)

### R5 · ใบกำกับภาษีลงวันที่อะไร (B3 ส่วนแรก)

**ระบบเดิม:** ใบกำกับภาษีลงวันที่ออกใบ (S14: ขาย 05/10 ออกใบ 13/10 ใบลงวันที่ 13/10)
**แต่รายงานภาษีขาย (เมนู 08 → รายงานภาษี) ลงรายการตามวันที่ขาย:** MA-TX261000001 / 002 / 003 ตัวเอกสารลงวันที่ 13/10
แต่ในรายงานอยู่วันที่ 05/10, 06/10 และ 04/10 ถ้าขายปลายเดือนแล้วออกใบต้นเดือนถัดไป ภาษีจะไปอยู่คนละเดือนกับวันที่บนใบกำกับ (บั๊กที่พบเพิ่ม)
ข้อกฎหมายที่เกี่ยวข้อง (ให้ผู้ทำบัญชียืนยัน): ขายสินค้าเกิดภาษีเมื่อส่งมอบ, งานบริการเกิดเมื่อรับเงินหรือเมื่อออกใบกำกับก่อนรับเงิน

**ทางเลือก (ใบกำกับและรายงานใช้วันเดียวกันเสมอ):**
- ก) วันที่ขาย (วันที่ของใบตัดสต็อก) ถ้าออกใบหลังเดือนนั้นยื่นภาษีไปแล้ว ระบบเตือน
- ข) วันที่ออกใบ (เหมือนตัวเอกสารเดิม) และย้ายรายงานไปตามวันที่ออกใบ
- ค) วันที่รับเงิน (ถ้ายังไม่รับเงินใช้วันที่ออกใบ)

**แนะนำ:** ก — ตรงกับใบกำกับอย่างย่อที่ลูกค้าได้ตอนขายและตรงกับรายงานเดิม
**รอคำตอบนี้:** PR ภาษี (ใบกำกับภาษี)

### R6 · ยกเลิกใบกำกับภาษีแล้วบิล การรับเงิน และสต๊อกเป็นอย่างไร (B3 ส่วนที่สอง)

**ระบบเดิม (S62):** ยกเลิก MA-TX261000003 แล้วบิลในทะเบียนลูกหนี้ถูกยกเลิกและกลับเป็น "ยังไม่ชำระ" แต่ใบตัดสต็อกยัง "ชำระแล้ว"
สต๊อกไม่คืน เงินที่รับยังอยู่ ข้อความบอก "ต้องเริ่มจากใบเสนอราคาใบใหม่" และออกใบกำกับใบใหม่แทนไม่ได้ ระบบเดิมไม่มีใบลดหนี้ฝั่งขาย

**ทางเลือก:**
- ก) ยกเลิกเฉพาะใบกำกับ (เช่น ชื่อหรือเลขผู้เสียภาษีผิด) บิล เงิน สต๊อกคงเดิม แล้วออกใบใหม่แทนได้
- ข) ยกเลิกทั้งการขาย: ใบกำกับ + การรับเงิน (บันทึกคืนเงิน) + คืนสต๊อก + บิลเป็นยกเลิก
- ค) ตอนกดยกเลิกให้เลือกเหตุผล "ออกใบใหม่แทน" (= ก) หรือ "ยกเลิกการขาย" (= ข)
- เพิ่มเติม: ใบกำกับของเดือนที่ยื่น ภ.พ.30 ไปแล้ว ง) ห้ามยกเลิก ต้องออกใบลดหนี้ (ทำใบลดหนี้เพิ่มหลังเปิดอู่นำร่อง) จ) ยกเลิกได้แต่เตือน

**แนะนำ:** ค และ จ ในช่วงนำร่อง (ทำใบลดหนี้แล้วเปลี่ยนเป็น ง) — แก้ข้อมูลที่ขัดกันตอนนี้ โดยไม่ต้องสร้างเอกสารใหม่ก่อนนำร่อง
**รอคำตอบนี้:** PR ภาษี (ใบกำกับภาษี)

### R7 · หัก ณ ที่จ่าย (B4)

**จะทำตามระบบเดิม (ตรงกับที่เจ้าของเคยตอบ):** หักจากยอดก่อน VAT อัตรา 1/2/3/5% ทั้งสองฝั่ง
- ลูกค้านิติบุคคลหักเรา: ระบบใส่ 3% ของค่าแรงให้เอง เปลี่ยนเป็นทั้งบิลก่อน VAT ได้ (S22: 3% × ค่าแรง 3,000 = 90, S25: 45) และบันทึก "ได้รับ 50 ทวิ แล้ว" พร้อมรูปได้
- เราหักผู้รับเงิน: S43 ค่าซ่อม 2,000 + ภาษีซื้อ 140 − หัก 3% 60 = จ่ายจริง 2,080

**จะแก้ (ข้อ 4):** ใบเสร็จเก็บยอดที่ถูกหักจริง ประวัติแสดงยอดหัก ตารางหัก ณ ที่จ่ายตรงกับตารางบิล
และตาราง "ภาษีถูกหัก ณ ที่จ่าย" ในรายงานภาษีที่แสดงฐานภาษี 0.00 (พบเพิ่ม: แถว MA-RE261000002 หัก 60, MA-RE261000003 หัก 30)

**คำถาม (ข้อ 12 และที่ค้างจาก B4):**
- (ก) ระบบออกหนังสือรับรอง 50 ทวิ เมื่อ**เรา**เป็นผู้หัก (มีเลขที่ของตัวเองและสรุป ภ.ง.ด.3/53) — กฎหมายให้ผู้หักออกให้ผู้ถูกหัก
  ก) ทำในเฟส 3 ก่อนนำร่อง ข) ทำหลังนำร่อง (ช่วงนำร่องผู้ทำบัญชีออกเองจากรายงานภาษีที่มีอยู่) ค) ไม่ทำ
- (ข) จ่ายเจ้าหนี้ (S31) ไม่มีเลขที่ใบสำคัญจ่ายและไม่มีช่องหัก ณ ที่จ่าย

**แนะนำ:** (ก) = ข เพราะเป็นเอกสารใหม่ ไม่ใช่การย้าย logic · (ข) = ก เงินที่จ่ายออกทุกบาทควรมีเลขเอกสารเหมือนฝั่งรับ

## 3) สต๊อกและต้นทุน FIFO

### R9 · ขายเกินของที่มี (สต๊อกติดลบ) และต้นทุนชั่วคราว

**ระบบเดิม (ทดลองเพิ่ม):** BR-001 เหลือ 19 ขาย 25 → ขึ้น "สต๊อกไม่พอ" ให้กด "ตัดสต็อก (ยอมติดลบ)" → สต๊อก −6
ต้นทุน 6 ชิ้นที่ขาดคิดชั่วคราวที่ทุนในทะเบียน 850 พอรับของล็อตใหม่ 10 ชิ้นทุน 870 **ต้นทุนของบิลเก่าเปลี่ยนเอง** จาก 21,250 เป็น 21,370
ถ้าของมาถึงเดือนถัดไป กำไรของเดือนก่อนจะเปลี่ยนหลังปิดเดือน ใครตัดสต็อกได้ก็กดยอมติดลบได้

**ทางเลือก:**
- ก) ยอมติดลบเมื่อยืนยัน และแก้ต้นทุนบิลเก่าย้อนหลังเหมือนเดิม
- ข) ยอมติดลบเมื่อยืนยัน แต่บิลเก่าคงต้นทุนชั่วคราว ส่วนต่างลงเดือนที่ของเข้า
- ค) ห้ามขายเกินของที่มี
- เพิ่มเติม: ง) ทุกคนที่ตัดสต็อกได้กดยอมติดลบได้ (เดิม) จ) เฉพาะเจ้าของหรือผู้มีสิทธิ์อนุมัติ

**แนะนำ:** ข และ ง — อู่ยังขายได้ตอนของมาไม่ทัน แต่ตัวเลขเดือนที่ปิดแล้วไม่เปลี่ยน

### R10 · ของขาด/เกินจากการตรวจนับ การเบิกใช้ภายใน และทุนในทะเบียน (B7)

รายการเคลื่อนไหวสต๊อกเก็บต้นทุน 0 และเครื่องหมายขาออกไม่เหมือนกัน (ข้อ 9 จะแก้ให้เก็บต้นทุน FIFO จริง)
เจ้าของเคยตอบ: ของหายบางกรณีตีเป็นขาย, ทุนในทะเบียนใช้ตัวที่ต่ำกว่า

**คำถาม:**
- (ก) ของขาด: ก) ลงค่าใช้จ่าย "สินค้าขาด" ตามทุน FIFO เป็นค่าตั้งต้น ถ้ามีคนรับผิดชอบ ให้เปิดใบขายปกติให้คนนั้นแทน (มี VAT) ข) ลงค่าใช้จ่ายเสมอ ค) ตีเป็นขายเสมอ
- (ข) ของเกิน: ก) เข้าสต๊อกที่ทุนในทะเบียนและลงเป็นรายได้อื่น (หรือหักกับของขาดเดือนเดียวกัน) ข) เข้าสต๊อกทุน 0
- (ค) เบิกใช้ภายใน: ก) ลงค่าใช้จ่ายตามทุน FIFO (เลือกหมวดได้) ข) ไม่ลง (เดิม)
- (ง) ทุนในทะเบียน (ใช้คิดต้นทุนชั่วคราวใน R9 ทุนยอดยกมา และราคาขายตามกำไร A/B/C): ก) ตัวที่ต่ำกว่าระหว่างราคาซื้อล่าสุดกับทุนเฉลี่ยของที่เหลือ ข) ราคาซื้อล่าสุด (เดิม) ค) ทุนเฉลี่ยของที่เหลือ

**แนะนำ:** ก ทุกข้อ — ตรงกับที่เจ้าของเคยตอบ และงบไม่แสดงกำไรเกินจริง
**รอคำตอบนี้:** PR ตัดสต๊อก FIFO, PR ค่าใช้จ่าย/รายงาน

## 4) เงินเดือนและประกันสังคม

### R12 · ประกันสังคม (B1)

**ระบบเดิม (S40):** ฐาน = เงินเดือนอย่างเดียว ขั้นต่ำ 1,650 เพดาน 15,000 อัตรา 5% ปัดเป็นบาท หักสูงสุด 750 นายจ้างสมทบเท่ากัน
(11 คน ฝั่งละ 8,050; EMP003 เงินเดือน 12,000 หัก 600) แต่ละร้านแก้อัตรา ขั้นต่ำ เพดาน และยอดสูงสุดเองได้ในหน้าตั้งค่า
เจ้าของเคยตอบ: ฐานรวมเงินได้ประจำ (เช่น ค่ารถเดือนละ 1,000 + เงินเดือน 12,000 = 13,000) เพดาน 17,500 (หักสูงสุด 875)

**จะทำ (ยืนยัน):** ฐาน = เงินเดือน + เงินได้ประจำรายเดือน (เพิ่มช่องในข้อมูลพนักงาน) ไม่รวมค่าล่วงเวลาและเงินพิเศษ ·
ลูกจ้าง 5% นายจ้าง 5% · ฐานขั้นต่ำ 1,650 · เพดาน 17,500 ในปี 2569–2571 (ตามที่ประกาศไว้จะขึ้นเป็น 20,000 ในปี 2572 และ 23,000 ในปี 2575 — ตรวจกับประกาศจริงก่อนใช้) · ปัดเป็นบาท

**คำถาม:** ใครตั้งอัตราและเพดาน
- ก) ระบบตั้งจากตารางกลางตามวันที่มีผล ร้านแก้ไม่ได้ (เราอัปเดตเมื่อกฎหมายเปลี่ยน)
- ข) ร้านแก้เองได้เหมือนเดิม
- ค) ระบบตั้งให้ แต่ร้านแก้ได้ (มีคำเตือนและลง audit)

**แนะนำ:** ก — ตัวเลขตามกฎหมายเหมือนกันทุกร้าน ร้านไม่ต้องตามประกาศเอง
**รอคำตอบนี้:** PR เงินเดือน/ประกันสังคม

**คำถาม:**
- (ก) วันที่และสถานะ: ก) ลงค่าใช้จ่ายวันสิ้นงวด สถานะค้างจ่าย แล้วกด "จ่าย" เลือกวันที่และวิธีจ่าย (ถ้าจ่ายวันนั้นเลยกดครั้งเดียวได้) ข) ถามวันที่จ่ายและวิธีจ่ายตอนบันทึก สถานะจ่ายแล้วทันที ค) เหมือนเดิม
- (ข) ค่าล่วงเวลา/เงินพิเศษ: ก) กรอกในหน้าจ่ายเงินเดือนทุกงวด (เริ่มที่ 0) ข) คงที่ในข้อมูลพนักงาน (เดิม)
- (ค) บันทึกงวดเดิมซ้ำ: ก) ไม่ได้ ต้องยกเลิกงวดเดิมก่อน ข) ได้เมื่อยืนยัน (เดิม)
- (ง) สลิปเงินเดือนรายคน: ก) มี (พิมพ์/PDF) ข) ไม่มี
- (จ) เริ่มงานหรือลาออกกลางเดือน: ก) เงินเดือน ÷ 30 × จำนวนวันที่ทำงานในเดือน ข) ÷ จำนวนวันจริงของเดือน ค) เต็มเดือน (เดิม)
- (ฉ) ภาษีเงินได้หัก ณ ที่จ่ายของพนักงาน: ก) ยังไม่คำนวณ (เดิม) ข) คำนวณ

**แนะนำ:** ก ทุกข้อ — ค่าใช้จ่ายอยู่ถูกเดือน ตัวเลขแต่ละงวดตรงกับที่จ่ายจริง และลูกจ้างมีหลักฐาน
**รอคำตอบนี้:** PR เงินเดือน/ประกันสังคม

## 5) สิทธิ์

### R14 · "ไม่เห็นราคา" ครอบคลุมอะไร และข้อมูลที่ส่งถึงเครื่องพนักงาน

**ระบบเดิม:** ตั้งสิทธิ์ละเอียดรายคนได้แล้ว: เมนู 13 เมนู, คอลัมน์สต๊อก 17 คอลัมน์ (รวม "ทุน" และ "ราคาขาย A/B/C"),
"เห็นยอดเงินหน้าแรก" และปุ่ม ดู/เพิ่ม/แก้/อนุมัติ/ยกเลิก/พิมพ์/ส่งออก/เฉพาะของตัวเอง ราว 150 ปุ่ม
ช่างที่ปิดทุนและราคาขาย ยังเห็นมูลค่าทุนรวมในหน้าสต๊อกและยอดเงินในใบเสนอราคา (S47, ข้อ 13 และ 42 ซึ่งอนุมัติให้แก้แล้ว)
นอกจากนี้ **ข้อมูลทั้งร้านถูกส่งไปที่เบราว์เซอร์ของพนักงานทุกคนที่เข้าระบบ** รวมเงินเดือนและเลขบัตรประชาชนของพนักงานคนอื่น
และต้นทุนทุกรายการ (เฟส 2 ซ่อนแค่รหัสผ่าน) คนที่เปิดเครื่องมือของเบราว์เซอร์เป็นจะเห็นได้

**คำถาม (ก) ปิดสิทธิ์แล้วซ่อนอะไร:**
- ก) ปิด "ทุน" = ไม่เห็นต้นทุนทุกที่ (มูลค่าสต๊อก ล็อต FIFO กำไร ราคาซื้อในใบรับสินค้า) · ปิด "ราคาขาย" = ไม่เห็นราคาและยอดเงินในใบเสนอราคาและใบตัดสต็อก (เห็นรายการและจำนวน)
- ข) ปิด "ราคาขาย" ซ่อนแค่คอลัมน์ราคาในหน้าสต๊อก ยังเห็นยอดเงินในเอกสาร (เพื่อบอกลูกค้า)

**คำถาม (ข) ต้องกันข้อมูลที่ส่งถึงเครื่องเมื่อไร:**
- ก) เฟส 3: server ไม่ส่งเงินเดือน เลขบัตรประชาชน และต้นทุน ให้คนที่ไม่มีสิทธิ์เห็น
- ข) เฟส 3 ซ่อนบนหน้าจออย่างเดียว ตัดข้อมูลที่ส่งเมื่อย้ายหน้าจอไป React (เฟส 4)

**แนะนำ:** (ก) = ก ตรงกับชื่อสิทธิ์ที่ตั้ง · (ข) = ก อย่างน้อยเงินเดือนและเลขบัตรประชาชน เพราะเป็นข้อมูลส่วนบุคคล (PDPA) ที่ร้านต้องดูแล
**รอคำตอบนี้:** PR สิทธิ์ และก่อนเปิดอู่นำร่อง

## 6) Audit log

### R15 · เก็บประวัติการใช้งานนานเท่าไร เก็บอะไร ใครดูได้

**ระบบเดิม:** บันทึก วันเวลา ผู้ใช้ เอกสาร การกระทำ (27 แบบ รวมการเปิดดูและสั่งพิมพ์) และข้อความสั้น ไม่เก็บค่าก่อน/หลังแก้
**เมื่อเกิน 4,000 รายการ ระบบลบของเก่าทิ้งเหลือ 3,000 รายการล่าสุดโดยไม่บอก** (พบเพิ่ม) อู่ขนาดกลางถึงจุดนี้ในไม่กี่เดือน
ใครเปิดเอกสารได้ก็กด "ตรวจสอบเอกสาร" ดูประวัติของเอกสารนั้นได้ และคนที่เข้าเมนู 08 ได้ดูรายงานรวมทั้งร้าน
(การลงประวัติทุกการเปลี่ยนแปลงตัดสินแล้วใน A3/A6)

**คำถาม:**
- (ก) อายุการเก็บ: ก) เก็บทั้งหมดตลอดที่ร้านยังมีบัญชี ข) เก็บ 10 ปี ค) เก็บ 5 ปี (ขั้นต่ำของเอกสารภาษี)
- (ข) รายละเอียด: ก) เก็บค่าก่อนและหลังแก้ทุกช่องที่เปลี่ยน (ดูได้ว่าแก้อะไรจากอะไร) ข) ข้อความสั้นเหมือนเดิม
- (ค) ผู้ดู: ก) เหมือนเดิม (ประวัติรายเอกสาร = คนเปิดเอกสารได้, รายงานรวม = คนเข้าเมนู 08 ได้) ข) รายงานรวมเฉพาะเจ้าของร้านและ HQ

**แนะนำ:** ก, ก, ข — ข้อมูลไม่ใหญ่ เก็บได้ตลอด รู้ชัดว่าใครแก้อะไร และรายงานรวมอยู่กับคนที่รับผิดชอบ
**รอคำตอบนี้:** PR audit log

## 7) การเก็บเงินและวันหมดอายุ (A2)

### R16 · ร้านจ่ายเงินอย่างไร และหมดอายุแล้วเกิดอะไร

**ระบบเดิม (ปิดไว้ด้วยโหมดพัฒนา):** ทดลองใช้ 15 วัน ครบแล้ว**ล็อกทั้งระบบ** ขึ้น "ครบกำหนดทดลองใช้ 15 วันแล้ว … ข้อมูลทั้งหมดของร้านยังถูกเก็บไว้ครบถ้วน"
เจ้าของร้านเห็น "แพ็กเกจรายปี 12,000 บาท/ปี (ราคาเดโม)" กดชำระ (จำลอง) แล้วปลดล็อกทันที พนักงานเห็น "แจ้งเจ้าของร้าน"
ในหน้าตั้งค่ายังมีปุ่ม "ต่ออายุ +1 ปี" ที่เจ้าของกดเองได้ไม่จำกัดโดยไม่จ่ายเงิน (S55) แฟรนไชส์มีวันหมดอายุแยกรายสาขา (HQ ใช้ของสาขาแรกชั่วคราว S120)
ตอนนี้ทีมงานเปิดร้านด้วยสคริปต์ (P3)

**คำถาม:**
- (ก) ราคาและหน่วยคิดเงิน: ราคาต่อปีของ Biz / ProX / Franchise เท่าไร, Franchise คิดต่อเครือหรือต่อสาขา, ทดลองใช้กี่วัน, อู่นำร่องคิดเงินหรือไม่ — *ขอเป็นตัวเลข*
- (ข) วิธีต่ออายุ: ก) ร้านโอนเงินแล้วส่งสลิป ทีมงานกดต่ออายุในหน้าผู้ดูแล ข) จ่ายออนไลน์ (QR พร้อมเพย์/บัตร ผ่านผู้ให้บริการรับชำระ) ต่ออายุอัตโนมัติ ค) ทั้งสองแบบ
- (ค) เมื่อหมดอายุ: ก) ล็อกทั้งระบบ (แบบที่ระบบเดิมออกแบบไว้) ข) เตือนล่วงหน้า 14 วัน หลังหมดอายุเปิดดู พิมพ์ และส่งออกข้อมูลได้ แต่สร้างหรือแก้ไม่ได้ ค) ใช้ต่อได้อีก N วันแล้วจึงเป็นแบบ ข
- (ง) เลิกใช้แล้วเก็บข้อมูลร้านนานเท่าไร: ก) 12 เดือน ส่งออกได้ตลอด แจ้งก่อนลบ 30 วัน ข) 5 ปี (เท่าอายุเอกสารภาษี) ค) อื่น ๆ (ระบุ)
- (จ) DriveGo ต้องออกใบเสร็จ/ใบกำกับภาษีค่าบริการให้ร้านจากระบบนี้หรือไม่

**แนะนำ:** (ข) = ก ช่วงนำร่อง แล้วเพิ่ม ข เมื่อร้านเยอะ · (ค) = ข ร้านยังเปิดดูและพิมพ์เอกสารเดิมให้ลูกค้าได้ · (ง) = ก · (ก), (จ) ขอให้เจ้าของระบุ
**รอคำตอบนี้:** ก่อนเปิดใช้จริงกับร้านที่จ่ายเงิน (อู่นำร่องเปิดด้วยสคริปต์ตาม P3 ได้ระหว่างรอ) · ระหว่างนี้ปุ่ม "ต่ออายุ +1 ปี" จะถูกปิดตาม A2

## 8) อื่น ๆ

### R17 · เคลมผู้ขาย ซื้อสินทรัพย์ และค่าเสื่อม (B8) ทำเมื่อไร

**ระบบเดิม:** ผลเคลมแบบหักยอด (S64) คิดจากทุนก่อน VAT 1,960 จดไว้ที่ใบเคลมอย่างเดียว ไม่ลดเจ้าหนี้ ไม่มีใบลดหนี้ ของเสียไม่ลงค่าใช้จ่าย ·
ซื้อสินทรัพย์ (S65) ไม่มีรายการจ่ายเงิน เจ้าหนี้ หรือภาษีซื้อ (ภาษีซื้อของสินทรัพย์จึงไม่อยู่ในรายงาน ภ.พ.30) ค่าเสื่อมคิดเต็มเดือนแม้ได้มากลางเดือน มูลค่าซาก 1 บาท
เจ้าของเคยตอบ: เคลมต้องมีใบลดหนี้ทุกกรณี, ซื้อสินทรัพย์ต้องตั้งเจ้าหนี้และภาษีซื้อ (ยกเว้นผู้ขายไม่จด VAT), ต้องมีโมดูลสินทรัพย์พร้อมช่องมูลค่าซาก

**คำถาม:**
- (ก) ทำเมื่อไร: ก) ภาษีซื้อและเจ้าหนี้ของสินทรัพย์ทำในเฟส 3 (กระทบ ภ.พ.30) ส่วนใบลดหนี้เคลมและโมดูลสินทรัพย์ทำหลังนำร่อง ข) ทั้งหมดในเฟส 3 ค) ทั้งหมดหลังนำร่อง
- (ข) ค่าเสื่อมปีแรก: ก) ตามจำนวนวันที่มีสินทรัพย์ ข) เต็มเดือนตั้งแต่เดือนที่ได้มา (เดิม)

**แนะนำ:** (ก) = ก แก้ส่วนที่ทำให้ยื่นภาษีผิดก่อน · (ข) = ก ตามที่สรรพากรใช้คิดเป็นรายวัน (ให้ผู้ทำบัญชียืนยัน)
**รอคำตอบนี้:** PR ภาษี (ภาษีซื้อสินทรัพย์), งานหลังนำร่อง

### R18 · ProX โหมดออนไลน์ (ข้อ 62–65 ใหม่)

**ระบบเดิม (S123–S125 กับ server เครือจำลอง):** รับคิวจองของลูกค้าเดิมที่มีรถหลายคัน ใบเสนอราคาได้รถคันแรกเสมอ ไม่ใช่คันที่จอง (ข้อ 62) ·
ออกใบเสร็จและรับชำระผ่านเครือ **ไม่บันทึกอะไรในร้าน** ไม่มีใบเสร็จ รายการรับเงิน หรือ audit (ข้อ 63) ·
รับของจากคลังกลางเพิ่มแค่จำนวน (ข้อ 64 ดู R11) · ตารางโหลดใหม่ทุก 7 วินาทีจนตัวเลขที่กำลังพิมพ์หาย (ข้อ 65) · server เครือจริงยังไม่มี และตัดสินแล้วว่าเป็นโครงการแยกหลังเฟส 3 (Q4)

**ทางเลือก:**
- ก) อู่นำร่องยังไม่เปิดปุ่ม "เชื่อมต่อสาขา" ของ ProX ตัดสินข้อ 63 และ 65 ตอนทำระบบเครือจริง ส่วนข้อ 62 แก้ (บั๊กเดียวกับข้อ 29 ที่อนุมัติแก้แล้ว)
- ข) แก้ทั้งหมดในเฟส 3: เงินที่รับผ่านเครือลงใบเสร็จและรายการรับเงินในร้านด้วย
- ค) คงเดิมทั้งหมด

**แนะนำ:** ก — ไม่มี server เครือจริงให้ต่อ จึงยังไม่ควรเปิดให้อู่ใช้ (งาน "ProX ดึงข้อมูลทุก 7 วินาที → SSE" ในแผนเฟส 3 จึงย้ายไปทำพร้อมระบบเครือ)
**รอคำตอบนี้:** ก่อนเปิดอู่นำร่อง (ถ้าอู่นำร่องเป็น ProX)

### R19 · ทุกเครื่องเห็นการเปลี่ยนแปลงทันที เน็ตหลุด และไฟล์แนบ

**ระบบเดิม:** ข้อมูลอยู่ในเครื่องใครเครื่องมัน ทำงานได้แม้ไม่มีเน็ต ระบบใหม่ตัดสินแล้วว่าบันทึกที่ server
(บันทึกชนกันได้ข้อความตาม P1/Q5, เน็ตหลุดขึ้น "เชื่อมต่อ server ไม่ได้", เห็นการเปลี่ยนแปลงของคนอื่นทันทีตาม Q8)
ไฟล์แนบตอนนี้เก็บในข้อมูลร้าน: ไฟล์และคลิปในคลังความรู้ ProX (จำกัดไฟล์ ≤ 5MB คลิป ≤ 15MB ใหญ่กว่านั้นเก็บแค่ชื่อ "ระบบจริงอัปขึ้นเซิร์ฟเวอร์กลาง"),
รูปสลิปโอน, รูป 50 ทวิ ที่ได้รับ, รูปสินค้า (ย่อไม่เกิน 900px) และโลโก้

**คำถาม:**
- (ก) ถ้าเอกสารที่ฉันเปิดค้างอยู่ถูกคนอื่นแก้: ก) ขึ้นแถบแจ้งทันที "เอกสารนี้ถูกแก้ไขโดย <ชื่อ> เมื่อ <เวลา> — กดเพื่อโหลดข้อมูลล่าสุด" ข) ไม่แจ้ง รู้ตอนกดบันทึก (ข้อความชนกันของ P1)
- (ข) เน็ตหลุด (ยืนยัน): ก) ออกเอกสารและรับเงินไม่ได้จนกว่าเน็ตกลับ (เลขที่และสต๊อกอยู่ที่ server) ข) ต้องการโหมดขายหน้าร้านตอนเน็ตหลุดแล้วส่งทีหลัง (งานใหญ่ เลขที่อาจต้องออกทีหลัง)
- (ค) ไฟล์แนบ: ก) คงขนาดเดิม (ไฟล์ 5MB คลิป 15MB) พื้นที่รวมร้านละ 2GB ลบแล้วกู้คืนได้ 30 วัน ข) ขยายขนาด (เช่น คลิป 100MB) และคิดค่าพื้นที่เพิ่ม ค) ระบุเอง

**แนะนำ:** (ก) = ก ไม่ต้องรอจนกดบันทึกแล้วงานหาย · (ข) = ก · (ค) = ก ตัวเลขเริ่มต้น ปรับได้ภายหลังตามค่าใช้จ่ายจริง
**รอคำตอบนี้:** PR แจ้งการเปลี่ยนแปลงทันที (SSE), PR ไฟล์แนบ

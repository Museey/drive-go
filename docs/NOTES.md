## ขนาดระบบที่คาดไว้

บันทึกเมื่อ: 2026-10-14 (ตัวเลขจำนวนอู่และ user มาจากเจ้าของโปรเจกต์)

| | ช่วงแรก | 5 ปี |
|---|---|---|
| จำนวนอู่ | หลักร้อย | 2,000–3,000 |
| user ต่ออู่ | 2–3 (มากสุด 5) | 2–3 (มากสุด 5) |
| user รวม | ประมาณ 300–1,500 | ประมาณ 4,000–15,000 |
| server ที่น่าจะพอ | API 1 เครื่อง + PostgreSQL แบบ managed | API 2–3 เครื่อง + PostgreSQL ที่ใหญ่ขึ้น (เพิ่ม read replica ถ้ารายงานหนัก) |
| ปริมาณข้อมูล | ไม่กี่ GB | ประมาณ 15–18 GB ต่อปี รวม 5 ปีหลักสิบ GB |

ที่มาของปริมาณข้อมูล: วัดจากข้อมูลทดสอบ 36 เดือน (`seedDemo36()`) ซึ่งเป็นอู่ยอดขาย 2–5 ล้านบาทต่อเดือน
ได้ 15–18 MB ต่ออู่ (ในรูป JSON) หรือประมาณ 5–6 MB ต่ออู่ต่อปี อู่จริงส่วนใหญ่น่าจะเล็กกว่านี้
ส่วนที่ใหญ่ที่สุดคือ `fifo` 4.7 MB, `receipts` 3.7 MB (2,055 ใบ), `quotes` 3.5 MB และ `stockCuts` 3.3 MB

สรุป:
- ระบบนี้เป็นขนาดกลาง PostgreSQL ตัวเดียวรองรับได้ ยังไม่ต้องใช้ microservices หรือ Kubernetes
- ไฟล์เดิมบันทึกข้อมูลทั้งก้อนทุกครั้งที่เรียก `save()` ก่อนย้ายขึ้น server ต้องเปลี่ยนเป็นบันทึกเฉพาะรายการที่เปลี่ยน
  ไม่อย่างนั้นทุกการบันทึกจะส่งข้อมูล 15–18 MB และคนที่บันทึกทีหลังจะเขียนทับข้อมูลของคนอื่น
- ทดสอบรับโหลด (เช่นด้วย k6) เมื่อถึง 500, 1,000 และ 3,000 อู่ แทนการออกแบบเผื่อ 5 ปีตั้งแต่วันแรก

## การแยกข้อมูลแต่ละอู่ด้วย `shop_id`

บันทึกเมื่อ: 2026-10-14

### ข้อตัดสินใจ
ทุกอู่ใช้ฐานข้อมูล PostgreSQL ชุดเดียวกัน แยกข้อมูลของแต่ละอู่ด้วยคอลัมน์ `shop_id`
ไม่แยกฐานข้อมูลอู่ละก้อน เพราะ 2,000–3,000 ฐานข้อมูลต้อง migrate และ backup ทีละก้อน ดูแลยากมาก

### กติกา
- ทุกตารางที่เป็นข้อมูลของอู่ต้องมี `shop_id` ข้อมูลระดับสาขาต้องมี `branch_id` ด้วย
- index ขึ้นต้นด้วย `shop_id` เช่น `(shop_id, date)`
- `shop_id` ต้องมาจาก session ฝั่ง server เท่านั้น ห้ามใช้ค่าที่ browser ส่งมา
- เครือ Franchise นับเป็น 1 `shop_id` และแยกสาขาด้วย `branch_id` โดย HQ เห็นทุกสาขาในเครือ (เจ้าของโปรเจกต์ยืนยันแล้ว 2026-10-14)

### ความเสี่ยงและวิธีป้องกัน
ความเสี่ยง: ถ้าโค้ดจุดไหนลืมกรอง `shop_id` อู่หนึ่งจะเห็นหรือแก้ข้อมูลของอีกอู่ได้

- เปิด Row-Level Security ของ PostgreSQL เป็นด่านสุดท้าย ให้ฐานข้อมูลกรองเองตาม `shop_id` ของ request นั้น แม้โค้ดจะลืมกรอง
- ส่ง `shop_id` ให้ฐานข้อมูลด้วย `SET LOCAL` ภายใน transaction เพื่อไม่ให้ค่าค้างข้าม connection เมื่อใช้ connection pool
- ต้องมี test ใน CI ที่ล็อกอินเป็นอู่ A แล้วยืนยันว่าทุก API อ่านหรือแก้ข้อมูลของอู่ B ไม่ได้เลย

## ProX ดึงข้อมูลจาก server ถี่เกินไป (polling)

บันทึกเมื่อ: 2026-10-14

### ปัญหา
โหมดออนไลน์ของ ProX ดึงข้อมูลจาก server ประมาณ **3 ครั้งทุก 7 วินาทีต่อ user**
ถ้ามี 1,000 คนออนไลน์ จะเป็นประมาณ **430 request ต่อวินาที** จากการดึงข้อมูลอย่างเดียว
ทั้งที่ส่วนใหญ่ไม่มีอะไรเปลี่ยน

ที่มา: บรรทัด 19117 ในฟังก์ชัน `pxNetToggle()` เมื่อกด "เชื่อมต่อสาขา" จะตั้ง `setInterval(..., 7000)` ที่เรียก:

| ฟังก์ชัน | request | ความถี่ |
|---|---|---|
| `pxNetPull()` | `GET /api/queue` | ทุก 7 วินาที |
| `dcPull()` | `GET /api/dc/products` และ `GET /api/dc/requests` | ทุก 7 วินาที (2 request) |
| `pxStockReport(false)` | `POST /api/stock/report` | ประมาณทุก 55 วินาที (เฉพาะบัญชีสาขา) |

`/api/dc/products` ส่งรายการสินค้าทั้งหมดกลับมาทุกครั้ง จึงหนักทั้งจำนวน request และขนาดข้อมูล

### ประมาณการตามขนาดที่คาดไว้
ใช้ตัวเลขจากหัวข้อ "ขนาดระบบที่คาดไว้" ข้างบน
ระบบหลังบ้านมักเปิดหน้าจอค้างไว้ทั้งวัน ตัวเลขด้านล่างจึงคิดจากกรณีสูงสุดที่ทุกคนเปิดโหมดออนไลน์พร้อมกัน

| ระยะ | อู่ | user | request ต่อวินาทีจาก polling |
|---|---|---|---|
| ช่วงแรก | ~300 | ~900 | ~390 |
| 5 ปี | ~2,500 | ~7,500 | ~3,200 |

### แนวทางแก้
- เปลี่ยนเป็นให้ server ส่งข้อมูลมาเองเมื่อมีอะไรเปลี่ยน (WebSocket หรือ SSE) เช่น มีคิวจองใหม่ หรือคำขอเบิกจาก DC เปลี่ยนสถานะ
- รายการสินค้า DC: โหลดครั้งเดียวตอนเชื่อมต่อ หลังจากนั้นรับเฉพาะรายการที่เปลี่ยน
- รายงานสต๊อก: ส่งเมื่อสต๊อกเปลี่ยนจริง แทนการส่งตามเวลา
- ต้องรันบน server หรือ container ที่ทำงานตลอดเวลา (ไม่ใช่ serverless ล้วน) เพราะต้องรักษาการเชื่อมต่อค้างไว้
- ทางบรรเทาชั่วคราวระหว่างยังไม่แก้: หยุด polling เมื่อแท็บไม่ได้เปิดดูอยู่ (Page Visibility API)

## ข้อควรระวังของระบบ test (เฟส 0)

บันทึกเมื่อ: 2026-10-14

- **ภาพหน้าจอเฉลยขึ้นกับเครื่องที่ใช้ถ่าย** (เวอร์ชัน Chromium และไลบรารีของระบบปฏิบัติการ) เฉลยชุดนี้ถ่ายใน cloud container
  ด้วย Playwright 1.56.1 ถ้าจะตั้ง CI ต้องรันใน environment เดียวกัน (เช่น Docker image เดียวกัน)
  ไม่อย่างนั้นการเทียบภาพจะไม่ผ่านแม้โค้ดไม่ได้เปลี่ยน ถ้าต้องย้าย environment ให้บันทึกเฉลยภาพใหม่จากระบบเดิมในเครื่องใหม่
- **ข้อมูลตั้งต้นถูกเขียนลงเบราว์เซอร์เองก่อนเปิดโปรแกรม** ไม่ใช้ `storageState` ของ Playwright
  เพราะเคยเจอครั้งหนึ่งที่โปรแกรมอ่าน IndexedDB ก่อนข้อมูลถูกใส่ แล้วสร้างข้อมูลทดลอง 36 เดือนขึ้นมาเอง
- **สร้าง fixture ใหม่ได้เนื้อหาเดิม แต่ id อาจไม่เหมือนเดิม** ระบบเดิมมีงานที่ตั้งเวลาไว้ซึ่งดึงเลขสุ่มก่อนสร้างข้อมูลทดลอง
  จำนวนครั้งขึ้นกับจังหวะเวลาของเครื่อง (ที่เคยบอกว่าตรงกันทุกไบต์ เป็นเพราะบังเอิญ) เฉลยแทน id ด้วยชื่อที่อ่านได้จึงไม่กระทบ
  ไฟล์ fixture ที่ commit ไว้คือตัวอ้างอิง สร้างใหม่เฉพาะเมื่อต้องเปลี่ยนข้อมูลตั้งต้น
- **fixture สร้างที่ 08:00 ส่วน test รันที่ 09:00 วันเดียวกัน** เพราะระบบเดิมสร้าง id และลำดับล็อต FIFO จาก `Date.now()`
  ถ้าใช้เวลาเดียวกัน ของที่สร้างใน test จะดูเก่ากว่าของใน fixture
- **ตัวเลขประมาณการก่อนหน้านี้ (ฟังก์ชันประกาศซ้ำ 54 ชื่อ ฯลฯ) ผิด** เพราะนับจากการค้นหาข้อความ
  ตัวเลขที่ถูกต้องอยู่ใน [BEHAVIORS.md](BEHAVIORS.md) ซึ่งสร้างจากการอ่านโค้ดจริงและการตรวจตอนโปรแกรมทำงาน
- **ฟังก์ชันที่ต้องใช้ server เครือจริง** (`pxNetAccept` รับคิวจากเครือ, `dcReceive` รับของจาก DC) ทดสอบในเฟส 0 ไม่ได้
  เพราะ test ไม่ต่ออินเทอร์เน็ต ให้เขียนสถานการณ์ในเฟส 2 เมื่อมี server ของเราเองแล้ว

## ข้อค้นพบจากเฟส 1 (แยกไฟล์)

บันทึกเมื่อ: 2026-10-18

- **ข้อความ "เปิดใบแจ้งหนี้ใบใหม่" ตอนเปิดโปรแกรมขึ้นตามจังหวะเวลา ไม่ใช่พฤติกรรม**
  ตอนเปิดโปรแกรม `boot()` เรียก `newInvoiceDoc()` ซึ่งขึ้นข้อความนี้ ส่วน script ท้ายไฟล์ (`frontend/js/43.js`)
  มีตัวปิดข้อความประเภท "เปิดใบ…ใบใหม่" ที่เจ้าของโปรเจกต์ขอไว้ (2026-10-09) ข้อความจะหลุดขึ้นเฉพาะเมื่ออ่านข้อมูลใน IndexedDB
  เสร็จก่อน script นั้นโหลดถึง ทดลองหน่วงการอ่านข้อมูล: ระบบเดิมหน่วง 30 ms ก็ไม่ขึ้นแล้ว ส่วน `frontend/` หน่วงแค่ 5 ms ก็ไม่ขึ้น
  การเปิดโปรแกรมครั้งที่สองในสถานการณ์เดียวกัน (เช่น S92) ระบบเดิมก็ไม่ขึ้นอยู่แล้ว
  รัน `frontend/` เทียบเฉลยเดิมรอบละ 2 ครั้ง ผ่าน 163/168 ครั้ง ที่เหลือ 5 ครั้งต่างกันแค่ข้อความนี้ ภาพและข้อมูลตรงทุกครั้ง
- **กรรมการลำดับขั้นตอนจึงไม่นับข้อความที่ขึ้นระหว่างเปิดโปรแกรม** (ก่อนหน้าเข้าระบบหรือตัวโปรแกรมพร้อมใช้, `open()` ใน `tests/support/legacy-app.mjs`)
  เจ้าของโปรเจกต์อนุมัติ และบันทึก `flow.json` ใหม่จากระบบเดิมทั้ง 84 เรื่อง ทุกเรื่องต่างจากเฉลยเดิมแค่ข้อความนี้ในขั้นแรก
  ภาพหน้าจอและข้อมูลไม่เปลี่ยน ถ้าไม่แก้ เฟส 2 ก็ผ่านไม่ได้อยู่ดี เพราะข้อมูลจะมาจาก server ซึ่งช้ากว่านี้มาก

## ข้อค้นพบจากเฟส 2 งาน T7 (เข้าระบบที่ server)

บันทึกเมื่อ: 2026-10-18

- **การตัดสินว่าเข้าได้หรือไม่และข้อความทุกกรณีอยู่ที่ server แล้ว** (`server/lib/auth.ts`) ลอกกติกาจากระบบเดิม
  และพิสูจน์ด้วยเฉลยที่บันทึกจากระบบเดิม: S101 (Biz ทุกกรณี) และ S102 (Franchise ทุกกรณี) รวมถึง `tests/db/auth.test.mjs`
  ร้านแพ็กเกจไหนใช้กติกาของแพ็กเกจนั้นตามที่บันทึกไว้กับร้านบน server ไม่ได้ดูจาก `?package=` ในลิงก์
- **รหัสผ่านและ PIN เก็บเป็น hash (argon2id) ในตาราง `users` เท่านั้น** ข้อมูลร้านที่ส่งให้เบราว์เซอร์มีค่าแทน `********`
  รหัสที่ผู้ใช้เพิ่งพิมพ์ (ตั้งรหัสพนักงาน, รีเซ็ตรหัส) ส่งไป server ครั้งเดียวเพื่อทำ hash
  แต่ยังค้างอยู่ในหน่วยความจำของหน้าจอนั้นจนกว่าจะโหลดหน้าใหม่ เพราะหน้าจอเดิมเก็บไว้ในข้อมูลก้อนเดียวกัน
  ข้อความที่ระบบเดิมแสดงรหัสให้ผู้ตั้งเห็น (เช่น "บัญชีพร้อมใช้ — แจ้งพนักงาน: … รหัสผ่าน 8888") ยังแสดงเหมือนเดิมตามกติกาข้อ 7
- **กรอกรหัสผิด** นับต่อบัญชี ถ้าชื่อผู้ใช้ไม่มีอยู่จริงไม่มีอะไรให้นับ (ได้ข้อความ "ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง" ทุกครั้ง)
  การตั้งรหัสใหม่ล้างตัวนับของบัญชีนั้น
- **ผลของ Q7 ต่อ S03**: ทั้งรหัสเดิมและรหัสใหม่เป็น "มีรหัส" ส่วนต่างข้อมูลของ S03 จึงว่าง (`{}`)
  การเปลี่ยนรหัสยังถูกตรวจในสถานการณ์เดียวกันด้วยการเข้าระบบ: รหัสเดิมเข้าไม่ได้ รหัสใหม่เข้าได้
- **การบันทึกที่ถูกปฏิเสธ (P1) เคยถูกหน้าจอ "กำลังบันทึกข้อมูล…" บัง** หน้าจอนี้ (`frontend/js/43.js`) ขึ้นระหว่างที่ `save()` ยังไม่จบ
  และการบันทึกที่ถูกปฏิเสธจะไม่จบจนกว่าจะโหลดหน้าใหม่ ผู้ใช้จึงกดปุ่ม "ตกลง" ไม่ได้ S109 จับได้
  แก้ใน `server/client/storage.ts`: ระหว่างถามให้โหลดใหม่ ซ่อนหน้าจอรอ
- **ยังเหลือของสำเนาทดสอบบนหน้าจอจนถึงเฟส 4**: ปุ่ม "เปลี่ยนแพ็กเกจ" และ "ทดสอบบัญชีอื่น" บนแถบด้านบน
  ("ทดสอบบัญชีอื่น" ตอนนี้ออกจากระบบที่ server ด้วย) และการเลือกแพ็กเกจด้วย `?package=` ในลิงก์

  ต้องให้ server บังคับแพ็กเกจของร้านในหน้าของร้าน (ทำพร้อม T10 การตรวจสิทธิ์ที่ server)

## ข้อค้นพบจากเฟส 3 งาน 3.2 (เลขที่เอกสารออกที่ server)

บันทึกเมื่อ: 2026-10-23

- **หน้าจอยังออกเลขเองเหมือนเดิม แต่ server เป็นคนตัดสิน**: แอปเดิมเอาเลขจากตัวนับ `DB.seq` (หนึ่งตัวต่อสาขา × ประเภท × เดือน เช่น `MA-SA2610`)

  ก่อนส่ง จึงไม่ชนกันเอง (`shiftLater` ใน `server/lib/numbers.ts`)

## ข้อค้นพบจากเฟส 3 งาน 3.3 (VAT และใบกำกับภาษี) — ส่วนที่ตอบไว้ชัดแล้ว

บันทึกเมื่อ: 2026-10-23, เพิ่ม 2026-10-25 หลังได้คำตอบ T1–T12 (PHASE3-QUESTIONS.md)

- **VAT ปัดเป็นสตางค์ครั้งเดียวต่อใบ** (R4): ระบบเดิมเก็บ VAT ไม่ปัด (7% ของ 1,234.50 = 86.415) แล้วปัดตอนแสดง ทั้งแสดง 86.41
  (เลขทศนิยมของคอมพิวเตอร์เก็บ 86.415 เป็น 86.41499…) ยอดรวม 1,320.92 จึงไม่เท่ากับ 1,234.50 + 86.41 และรายงานภาษีบวกยอดที่ไม่ปัด
  ระบบใหม่คิด VAT จากยอดรวมทั้งใบหลังหักส่วนลด (เหมือนเดิม) แล้วปัดเป็นสตางค์ ครึ่งปัดขึ้น (`round2`, `vatOf` ใน `frontend/js/03.js`)
  ยอดรวม = ยอดก่อน VAT + VAT ที่ปัดแล้ว ใช้กับใบเสนอราคา ใบเสร็จ/ใบตัดสต็อก ใบรับสินค้า ค่าใช้จ่าย และภาษีซื้อของสินทรัพย์
  ยอดปรับเพิ่ม/ลดของใบตัดสต็อกก็ปัดเป็นสตางค์ (S138) เฉลยเดิมทุกตัวยังผ่าน เพราะข้อมูลทดสอบไม่มีใบที่ VAT มีเศษเกินสตางค์
  หัก ณ ที่จ่ายและค่าธรรมเนียมบัตรยังคิดแบบเดิม (งาน 3.4 และ 3.5)
- **อัตรา VAT อยู่ในตารางเดียว** (`VAT_RATES` ตามวันที่มีผล ตอนนี้มีแถวเดียว 7%) เอกสารใหม่ได้อัตราจากตาราง (`vatDefault`)
  เอกสารเก็บอัตราของตัวเอง (`vat`) เหมือนเดิม ชื่อตัวเลือกในฟอร์ม ("VAT 7% (แยกนอก)", "7%") และหัวบรรทัดในเอกสารพิมพ์บางแบบยังเขียน 7% ไว้ตายตัว
  ถ้าอัตราเปลี่ยน ต้องเพิ่มแถวในตารางและเปลี่ยนตัวเลือกให้อ่านจากตาราง (ยังไม่ได้ทำ เพราะยังไม่มีอัตราอื่นให้ทดสอบ)
- **ใบกำกับภาษีลงวันที่ขายและเก็บยอดของตัวเอง** (R4, R5-ก): ใบที่ออกใหม่ (หน้า 4.6, ฟอร์มใบเสร็จ) ลงวันที่ของการขาย
  (วันที่เดียวกับที่รายงานภาษีขายลงรายการ) เก็บวันที่ออกจริง (`issued`) อัตรา ยอดก่อน VAT, VAT และยอดรวม ณ ตอนออก (`stampTaxDoc`)
  รายงานภาษีขายใช้ยอดของใบกำกับที่ยังใช้ได้ (`saleTaxOf`) การขายที่ไม่มีใบเต็มรูปใช้ยอดของบิลเหมือนเดิม
  ทะเบียน 4.6 กรองช่วงวันที่ตามวันที่ออก (ใบที่ออกวันนี้ยังขึ้นใน "วันปัจจุบัน") และแสดง "ออก <วันที่>" ใต้วันที่ขายเมื่อไม่ตรงกัน (ข้อความใหม่)
  ใบกำกับที่ออกไปก่อนหน้านี้ (ในข้อมูลเดิม) ไม่ถูกแก้: ยังลงวันที่ออกและคำนวณยอดจากบิลเหมือนเดิม
  คำเตือนเมื่อออกใบหลังเดือนนั้นยื่นภาษีแล้ว (R5-ก) รอการปิดงวดภาษี (T2–T5)
- **ยกเลิกใบกำกับภาษีไม่ยกเลิกบิลแล้ว** (R6-ก): ระบบเดิมยกเลิกใบกำกับจากทะเบียน 4.6 แล้วยกเลิกบิล (ใบตัดสต็อก) ด้วย ตั้งสถานะยังไม่ชำระ
  และบอกให้เริ่มจากใบเสนอราคาใบใหม่ ระบบใหม่ยกเลิกเฉพาะใบกำกับ (เหตุผลยังถามเหมือนเดิม) บิล การรับเงิน และสต๊อกไม่เปลี่ยน
  แล้วออกใบใหม่จากบิลเดิมได้ ใบใหม่ได้เลขถัดไป ลงวันที่ขาย และจดเลขที่ของใบที่ออกแทน (`replaces` รูปแบบเดียวกับที่ระบบเดิมใช้ตอนทำฉบับแก้ไข)
  ใบที่ยกเลิกยังอยู่ในทะเบียนพร้อมเหตุผล และไม่อยู่ในรายงานภาษีขาย (S136 แทน S62) ใบใหม่ที่พิมพ์ (ต้นฉบับและสำเนา)
  มีบรรทัด "ออกแทนใบกำกับภาษีเลขที่ … ลงวันที่ … ที่ยกเลิก เพราะ …" เหนือหมายเหตุท้ายใบ (T1)
  การยกเลิกใบตัดสต็อกยังยกเลิกใบกำกับของมันด้วยเหมือนเดิม
- **ไม่คิด VAT ต้องมีสิทธิ์และเหตุผล** (R4-ข, T12): ร้านที่จด VAT เลือก "ไม่คิด VAT" (ใบเสนอราคา ใบเสร็จ) หรือ "ไม่มี" (ใบตัดสต็อก)
  ได้เฉพาะเจ้าของและพนักงานที่มีสิทธิ์ใหม่ "เลือกไม่คิด VAT (ต้องใส่เหตุผล)" (`doc.noVat`) และต้องใส่เหตุผล
  (ปุ่ม "ตกลง" กดได้เมื่อพิมพ์แล้ว) เอกสารเก็บเหตุผล (`noVatReason`) ประวัติการใช้งานของการบันทึกมี "· ไม่คิด VAT: <เหตุผล>"
  ใบตัดสต็อกที่ดึงจากใบเสนอราคาหรือคัดลอกจากใบเดิมรับเหตุผลมาด้วย ไม่ถามซ้ำ บัญชีที่ไม่มีสิทธิ์ได้ข้อความ "บัญชีนี้ไม่มีสิทธิ์เลือกไม่คิด VAT"
  และอัตรายังเป็น 7% (S137) ตอนนี้ตรวจที่หน้าจอ การตรวจซ้ำที่ server อยู่ในงาน 3.9 (สิทธิ์ละเอียดที่ server)
- **สิทธิ์ใหม่ 3 ตัว** (T3, T10, T12): "เลือกไม่คิด VAT (ต้องใส่เหตุผล)", "ปิดงวดภาษี", "ออกใบลดหนี้" อยู่ในกลุ่ม "การเงิน" ของฟอร์มพนักงาน
  พนักงานเดิมไม่ได้ (ไม่มีการย้ายสิทธิ์ให้) ชุดผู้จัดการอู่ไม่ติ๊กให้ "ให้สิทธิทั้งหมด" ติ๊กให้ พนักงานใหม่ที่บันทึกจึงมีสามช่องนี้ในข้อมูล
  และประวัติการใช้งานกับรายการพนักงานนับสิทธิ์ทั้งหมด 68 แทน 65 (พนักงานเดิมยังนับ 65 จนกว่าจะบันทึกฟอร์มของคนนั้น) (S139 แทน S44, S140 แทน S59)
- **แก้บั๊กของระบบเดิม: บันทึกฟอร์มพนักงานแล้วบัญชีเข้าระบบหาย** (เจ้าของโปรเจกต์อนุมัติให้แก้ 2026-10-25):
  ระบบเดิม `saveEmp` สร้างข้อมูลพนักงานใหม่ทั้งก้อนจากฟอร์ม ไม่เก็บรหัสผ่านและสถานะบัญชี (`dgbPass`, `dgbActive`) ที่ออกจากหน้า 10
  พนักงานจึงเข้าระบบไม่ได้จนกว่าจะออกบัญชีใหม่ (ตรวจด้วยการรันระบบเดิมแล้ว) ระบบใหม่เก็บสองช่องนี้ไว้ตามเดิม (server เก็บรหัสเดิมไว้
  เพราะหน้าจอส่งค่าแทนรหัส `********` มา) ไม่มีเฉลยของระบบเดิมที่บันทึกฟอร์มของพนักงานที่มีบัญชี จึงไม่มีสถานการณ์เดิมที่เปลี่ยน
  S137 ตรวจว่าหลังเจ้าของบันทึกฟอร์ม บัญชียัง "ใช้งานได้" และพนักงานเข้าระบบด้วยรหัสเดิมได้
- **ข้อความใหม่** (T12, เจ้าของโปรเจกต์อนุมัติ 2026-10-25): ข้อความยืนยันและข้อความหลังยกเลิกใบกำกับ, "ไม่คิด VAT" / "เหตุผลที่ไม่คิด VAT",
  "บัญชีนี้ไม่มีสิทธิ์เลือกไม่คิด VAT", "ออก <วันที่>" ในทะเบียน 4.6, ชื่อสิทธิ์ใหม่ 3 ตัว
- **ปิดงวดภาษี** (F2, T2–T5): หน้า 08 → รายงานภาษี เดือนที่จบแล้วมีปุ่ม "ปิดงวดภาษี" (เจ้าของ และพนักงานที่มีสิทธิ์ "ปิดงวดภาษี")
  ยืนยันด้วยข้อความที่อนุมัติใน T12 แล้วหัวรายงานแสดง "ปิดงวดภาษีแล้ว <วันที่> · <ผู้ปิด>" เจ้าของเท่านั้นกด "เปิดงวดกลับ" ได้ ต้องใส่เหตุผล
  ทั้งปิดและเปิดลงประวัติการใช้งาน (ประเภท "งวดภาษี") และเก็บประวัติใน `DB.taxPeriods['YYYY-MM'].hist`
  เดือนปัจจุบันและเดือนถัดไปปิดไม่ได้ (ยังขายอยู่ เอกสารใหม่ลงวันที่วันนี้) จึงไม่ต้องล็อกการสร้างเอกสารขายใหม่
  เดือนที่ปิดแล้วล็อกเอกสารที่มี VAT ลงวันที่ในเดือนนั้น (ข้อความที่อนุมัติ "เดือน … ปิดงวดภาษีแล้ว ใช้ใบลดหนี้แทน"):
  ยกเลิก/ปรับยอด/ทำฉบับแก้ไขการขาย, ยกเลิกใบกำกับภาษี, ยกเลิกใบเสร็จ, แก้ใบเสร็จ ใบรับสินค้า ค่าใช้จ่าย สินทรัพย์ในส่วนที่มีผลต่อภาษี
  (วันที่ คู่ค้า เลขใบกำกับ รายการ ส่วนลด อัตรา VAT ยอด) และบันทึกเอกสารใหม่ลงวันที่ในเดือนนั้น, ยกเลิกใบรับสินค้า, ลบค่าใช้จ่าย/สินทรัพย์
  การรับเงินและจ่ายเงินทำได้ตามปกติ (รวมการแก้แค่สถานะจ่ายเงินในฟอร์มค่าใช้จ่าย/ใบรับสินค้า) (S141)
  ใบกำกับเต็มรูปของการขายในเดือนที่ปิดแล้วออกได้หลังคำเตือน ลงวันที่ขาย รายงานภาษีขายของเดือนนั้นยังแสดงเลขใบตัดสต็อกพร้อม
  "ออกใบเต็มรูปภายหลัง เลขที่ …" ยอดภาษีไม่เปลี่ยน (T2-ก)
  ข้อความใหม่ที่ยังไม่อยู่ใน T12 รอยืนยัน: "ปิดงวดภาษีแล้ว", "ยังไม่ปิด", "เปิดงวดกลับ", "เหตุผลที่เปิดงวดกลับ", "ปิดงวดภาษีเดือน … แล้ว",
  "เปิดงวดภาษีเดือน … กลับแล้ว", คำเตือนก่อนออกใบกำกับเต็มรูป ("ใบกำกับภาษีเต็มรูปลงวันที่ขาย … รายงานภาษีขายของเดือนนั้นยังแสดงเลขเดิม …
  และยอดภาษีไม่เปลี่ยน", ปุ่ม "ไม่ออก"), "ออกใบเต็มรูปภายหลัง เลขที่ …"
  ยังไม่ทำ: การตรวจซ้ำที่ server (ตอนนี้ล็อกที่หน้าจอ คนที่เรียก API ตรงยังแก้ได้) และช่องทางอนุมัติเอกสาร (`apvSaveDoc`) ที่บันทึกฟอร์มที่เปิดอยู่ตรง ๆ
- **ใบลดหนี้** (F2, T6–T10): หน้า 4.6 มีปุ่ม "+ ออกใบลดหนี้" (เจ้าของ และพนักงานที่มีสิทธิ์ "ออกใบลดหนี้") ค้นหาการขายที่มี VAT
  (ใบตัดสต็อกที่ยังไม่ยกเลิก ทั้งที่มีใบกำกับเต็มรูปหรือแค่อย่างย่อ, T7-ข) แล้วกรอก: กรณี (T6 ทั้ง 4 กรณี), จำนวนที่คืนและคืนเข้าสต๊อก/ของเสีย
  ทีละรายการ (สินค้าที่มีในสต๊อกเท่านั้น ค่าแรงลดด้วยกรณีลดราคา), หรือมูลค่าที่ลดก่อน VAT, และเหตุผล (ต้องกรอก) ใบลดหนี้ได้เลข MA-CN…
  ลงวันที่วันที่ออก VAT คิดและปัดแบบเดียวกับข้อ R4 ลดได้ไม่เกินยอดที่เหลือของการขาย (หักใบลดหนี้ก่อนหน้า รวมใบที่รออนุมัติ)
  ใบที่เจ้าของออกมีผลทันที ใบที่พนักงานออกรออนุมัติจากเจ้าของหรือผู้มีสิทธิ์อนุมัติใบกำกับภาษี (`apv.tax`) อยู่ในรายการรออนุมัติ (T10)
  เมื่อมีผล: ยอดของการขายลดลงด้วยรายการปรับลดที่ผูกเลขใบลดหนี้ ยอดค้างลดลงก่อน ส่วนที่เกินยอดค้างคืนเงินลูกค้า (เงินสด/เงินโอน, T8-ก)
  สินค้าที่คืนเข้าสต๊อกกลับเข้าล็อตเดิมด้วยต้นทุนเดิม (ต้นทุนขายของการขายลดลง) ของเสียไม่เข้าสต๊อก (T9-ก) และลงประวัติการใช้งาน
  ใบกำกับภาษีเดิม (เต็มรูปและอย่างย่อ) และรายงานภาษีขายของเดือนที่ขายไม่เปลี่ยน รายงานภาษีขายของเดือนที่ออกใบลดหนี้แสดงใบลดหนี้เป็นยอดติดลบ
  การขายที่มีใบลดหนี้ยกเลิกหรือทำฉบับแก้ไขไม่ได้ (จะคืนสต๊อกและยอดซ้ำ) ใช้ใบลดหนี้ "ยกเลิกการขายทั้งใบ" แทน (S142, S143)
  ปุ่มอยู่ที่ 4.6 ไม่อยู่ในหน้าต่างการขาย เพราะปุ่มเพิ่มในแถบเครื่องมือของหน้าต่างการขายทำให้ทุกอย่างข้างล่างเลื่อน (ภาพเฉลยของการขายที่บันทึกแล้วทุกภาพเปลี่ยน)
  หน้าต่างการขายแสดงเฉพาะปุ่มของใบลดหนี้ที่มีแล้ว
  ยังไม่ทำ: ยกเลิกใบลดหนี้ที่มีผลแล้ว, ทะเบียนใบลดหนี้แยก, เงินคืนลูกค้ายังไม่เข้ารายงานเงินสด/รายการรับเงินรายวัน (ทำในงาน 3.5),
  ยอดขายในรายงานกำไรขาดทุนลดลงในเดือนของการขายเดิม ไม่ใช่เดือนที่ออกใบลดหนี้ (รายงานภาษีถูกต้องตามเดือน), การตรวจซ้ำที่ server (งาน 3.9)
  ข้อความใหม่ทั้งหมดของใบลดหนี้รอยืนยัน (ชื่อกรณี หัวคอลัมน์ ปุ่ม ข้อความเตือน และหัวข้อในใบลดหนี้ที่พิมพ์)


## ข้อค้นพบจากเฟส 3 งาน 3.4 (หัก ณ ที่จ่าย)

คำตอบของเจ้าของโปรเจกต์: R7 (หัก ณ ที่จ่ายตามระบบเดิม + แก้ข้อ 4, ออก 50 ทวิ เมื่อเราเป็นผู้หัก, จ่ายเจ้าหนี้มีเลขใบสำคัญจ่ายและช่องหัก),
X1 (แก้) และคำตอบงาน 3.4 วันที่ 2026-10-25 ใน [PHASE3-QUESTIONS.md](PHASE3-QUESTIONS.md)

- **ยอดที่ลูกค้าหักเก็บที่การรับชำระแต่ละครั้ง** (ข้อ 4 "ใบเสร็จเก็บยอดที่ถูกหักจริง"): ระบบขายแบบใหม่ของระบบเดิมเก็บยอดหักจริงไว้ที่รายการรับชำระ
  (ใบเสร็จ MA-RE แต่ละใบ) อยู่แล้ว: `payments[].wht = { rate, base, baseAmt, amt, got, gotDate }` ส่วนช่อง `wht` ของบันทึกการขาย
  (อัตราในฟอร์มใบเสร็จแบบเดิม) เป็น 0 ตามการออกแบบ เพราะการรับแต่ละครั้งหักไม่เท่ากันได้ ปัญหาจริงคือที่ที่อ่านยอดหักจากช่องนั้น
  หรือไม่อ่านจากรายการรับชำระ ซึ่งแก้ตามข้อข้างล่าง
- **รายงานภาษี ตาราง "ภาษีถูกหัก ณ ที่จ่าย" แสดงฐานภาษี** (X1): ระบบเดิมแสดงฐาน 0.00 เพราะยอดรวมของการขายไม่มีฐานที่หัก
  ระบบใหม่ใช้ฐานที่บันทึกตอนรับชำระ (`baseAmt`) เช่น MA-RE261000002 ฐาน 2,000.00 หัก 3% 60.00 (S144)
- **หน้ารับชำระเงินลูกหนี้: ตารางหัก ณ ที่จ่ายแสดงคงค้างเท่ากับตารางบิล** (ข้อ 4): ระบบเดิมแสดงยอดก่อนหัก (S22: 3,766.40)
  ข้างตารางบิลที่แสดงยอดหลังหัก (3,676.40) ระบบใหม่แสดงยอดหลังหักทั้งสองตาราง (S144 แทน S22, S145 แทน S25)
- **ประวัติบอกยอดหัก** (ข้อ 4): ประวัติการใช้งานของการรับชำระจากหน้ารับชำระเงินลูกหนี้มี "· ลูกค้าหัก ณ ที่จ่าย X บาท"
  เหมือนการรับชำระจากหน้าต่างการขายที่มีอยู่แล้ว และหน้าต่าง "ประวัติการชำระเงิน" (08 → ลูกหนี้ → ประวัติชำระ) แสดง
  "หัก ณ ที่จ่าย X · ได้รับหนังสือรับรองแล้ว / รอหนังสือรับรอง" ใต้ยอดที่รับ ข้อความเดียวกับตาราง "การรับชำระของใบนี้" ในหน้าต่างการขาย
- ฝั่งลูกค้าหักเรา ระบบไม่ออก 50 ทวิ (ลูกค้าเป็นผู้ออก) เก็บรูปหนังสือรับรองที่ได้รับเหมือนเดิม
- **ใบสำคัญจ่าย MA-PV…** (R7-ข, คำตอบ 2026-10-25): เงินที่จ่ายออกทุกครั้งมีเลขที่ใบสำคัญจ่ายจากตัวนับของตัวเอง (`docNo('PV')`)
  - ค่าใช้จ่ายกิจการที่บันทึกเป็น "จ่ายแล้ว" ได้เลขตอนบันทึก วันที่จ่าย (`payDate`) = วันที่ของรายการ ส่วนที่กด "ค้างจ่าย" เพื่อจ่ายหรือแก้จาก
    ค้างจ่ายเป็นจ่ายแล้วได้วันที่จ่ายเป็นวันนั้น (ระบบเดิมไม่เก็บวันที่จ่ายของรายการที่บันทึกเป็นจ่ายแล้ว และไม่ลงประวัติตอนกดจ่าย)
    ประวัติการใช้งานมี "จ่ายเงิน X บาท (วิธีจ่าย) · หัก ณ ที่จ่าย Y บาท · ใบสำคัญจ่าย MA-PV…" (วิธีจ่าย "เครดิต (ยังไม่จ่าย)" ไม่ใส่)
    แก้กลับเป็นค้างจ่ายแล้วจ่ายใหม่ใช้เลขเดิม (เลขไม่ข้าม) ทะเบียนค่าใช้จ่ายทั้ง 4 หน้าแสดงเลขใบสำคัญจ่ายใต้เลขที่ (S146, S147)
  - ชำระเงินเจ้าหนี้: การจ่ายหนึ่งครั้งได้ใบสำคัญจ่ายใบเดียว แม้จ่ายหลายใบรับสินค้า (เลขเดียวกันในการจ่ายของทุกใบ) อยู่ในประวัติการใช้งาน
    กล่อง "บันทึกแล้ว" และประวัติชำระของใบรับสินค้า (S148, S149)
  - ใบสำคัญจ่ายที่พิมพ์: จ่ายให้ (ชื่อ ที่อยู่ เลขประจำตัวผู้เสียภาษี ดึงจากข้อมูลผู้ขาย ถ้าชื่อผู้รับเงินของค่าใช้จ่ายตรงกับผู้ขาย), รายการและเลขที่เอกสาร,
    รวม, หัก ภาษี ณ ที่จ่าย, จ่ายจริง (ตัวอักษร), วิธีจ่าย, ช่องเซ็น ผู้จ่ายเงิน ผู้อนุมัติ ผู้รับเงิน พิมพ์จากหน้าต่างค่าใช้จ่าย ประวัติชำระของใบรับสินค้า
    และกล่อง "บันทึกแล้ว" ของหน้าชำระเงินเจ้าหนี้ การพิมพ์ลงประวัติการใช้งาน
  - ไม่รวม: การจ่ายเงินเดือน (06 → 4 · จ่ายเงินเดือน สร้างค่าใช้จ่ายเอง ไม่ผ่านฟอร์มค่าใช้จ่าย) และใบรับสินค้าที่บันทึกเป็นเงินสดตอนรับของ
    (ไม่ผ่านหน้าชำระเงินเจ้าหนี้) ยังไม่มีใบสำคัญจ่าย รอถามเจ้าของโปรเจกต์
- **หัก ณ ที่จ่ายตอนจ่ายเจ้าหนี้** (R7-ข-ก): ปุ่ม "หัก ณ ที่จ่าย" ในหน้าชำระเงินเจ้าหนี้เปิดตารางของใบรับสินค้าที่ติ๊ก: ฐานก่อน VAT (เริ่มจากยอดก่อน VAT
  ของใบ แก้ได้เมื่อมีแค่บางส่วนเป็นค่าบริการ/ค่าขนส่ง) และอัตรา (ตัวเลือกเดียวกับฟอร์มค่าใช้จ่าย) ยอดหักลดยอดที่ต้องจ่ายและนับเป็นยอดที่ชำระแล้วของใบ
  (`paidAmtOf`) เหมือนลูกค้าหักเรา การจ่ายเก็บ `wht = { rate, baseAmt, amt, form }` แบบ ภ.ง.ด.53 ถ้าผู้ขายเป็นนิติบุคคล ไม่งั้น ภ.ง.ด.3 (S149)
- **ฟอร์มค่าใช้จ่ายไม่ทิ้งข้อมูลแล้ว**: ระบบเดิมสร้างรายการใหม่จากช่องในฟอร์มทุกครั้งที่บันทึก จึงทิ้งวันที่จ่าย เลขที่หนังสือรับรอง (50 ทวิ) แบบ ภ.ง.ด.
  และสถานะนำส่งที่บันทึกจาก 4.4 (พิมพ์ 50 ทวิ ซ้ำหลังแก้รายการได้เลขใหม่) ระบบใหม่เก็บช่องเหล่านี้ไว้ (S146 ตรวจเลขใบสำคัญจ่ายและวันที่จ่าย)
- **ไม่ได้แก้: หัวตารางเจ้าหนี้นับจำนวนใบไม่ตรง** (ข้อ 12 ส่วนที่สาม): หัวตาราง "ทะเบียนเจ้าหนี้" นับใบก่อนกรองสถานะ ("2 ใบ" ขณะที่ตารางว่าง S31)
  ทะเบียนลูกหนี้มีปัญหาเดียวกัน คำตอบ R7-ข ไม่ได้พูดถึงข้อนี้ จึงยังไม่แก้ รอถามเจ้าของโปรเจกต์ (เป็นเรื่องหน้าจอ แก้ได้ในเฟส 4)
- **ข้อความใหม่ที่รอยืนยัน** (ใบสำคัญจ่าย): "ใบสำคัญจ่าย", "PAYMENT VOUCHER", "พิมพ์ใบสำคัญจ่าย", "วันที่จ่าย", "จ่ายให้", "จ่ายจริง", "วิธีจ่าย",
  "ผู้จ่ายเงิน", "ผู้อนุมัติ", "ผู้รับเงิน", "ค่าสินค้าตามใบรับสินค้า", "(ใบกำกับ / ใบส่งของ …)", "จ่ายเงิน … บาท", "หัก ณ ที่จ่าย" (ปุ่ม),
  "หัก ณ ที่จ่ายผู้ขาย", "ฐานก่อน VAT", "อัตรา", "ยอดหัก (บาท)", "ติ๊กใบรับสินค้าที่จะจ่ายก่อน", "หัก ณ ที่จ่าย รวม … — ยอดที่ต้องจ่ายผู้ขาย …",
  "ยอดที่หักไม่ใช่เงินที่จ่าย — ระบบลดยอดคงค้างของบิลนั้นให้ · ออกหนังสือรับรอง (50 ทวิ) ได้ที่ 4.4 ใบหัก ณ ที่จ่าย · เราหักผู้ขาย",
  "หัก ณ ที่จ่าย ฿… — ไม่ใช่เงินที่จ่าย ระบบลดยอดคงค้างของบิลให้", "ยอดหัก ณ ที่จ่ายต้องน้อยกว่ายอดคงค้างของบิล"
- **ภ.ง.ด.3 / 53 นับตามวันที่จ่าย** (คำตอบ 2026-10-25): รายงานภาษี ตาราง "ภาษีหัก ณ ที่จ่ายที่กิจการต้องนำส่ง" และยอดในสรุปภาษี นับค่าใช้จ่ายที่จ่ายแล้ว
  ตามวันที่จ่าย (`payDate` ข้อมูลเดิมที่ไม่มีใช้วันที่ของรายการ) และการจ่ายเจ้าหนี้ที่หักไว้ตามวันที่จ่าย ค่าใช้จ่ายที่ยังค้างจ่ายยังไม่นับ (ยังไม่ได้หัก)
  ระบบเดิมนับค่าใช้จ่ายทุกรายการตามวันที่ของรายการ แม้ยังไม่จ่าย แต่ละแถวบอก "ภ.ง.ด.X ลำดับที่ N" (ลำดับในใบแนบ: วันที่จ่าย แล้วเลขที่เอกสาร
  นับแยกแต่ละแบบ) และท้ายตารางสรุปแต่ละแบบ: จำนวนราย (นับตามเลขประจำตัวผู้เสียภาษี ไม่มีใช้ชื่อ) ยอดเงินได้ และภาษี (S150)
  แบบของแต่ละรายการ: ค่าใช้จ่ายใช้ตามเดิม (ชื่อหรือเลขประจำตัวขึ้นต้น 0 = ภ.ง.ด.53 เปลี่ยนได้ที่ 4.4) การจ่ายเจ้าหนี้ใช้ประเภทของผู้ขาย
  ลำดับที่คำนวณใหม่ทุกครั้ง ถ้าบันทึกการจ่ายย้อนวันหลังพิมพ์ 50 ทวิ ไปแล้ว ลำดับที่อาจเลื่อน ควรพิมพ์ 50 ทวิ หลังบันทึกการจ่ายของเดือนครบ
- **หนังสือรับรอง 50 ทวิ ตามแบบสรรพากร** (R7-ก, คำตอบ 2026-10-25): 4.4 → เราหักผู้ขาย รวมการจ่ายเจ้าหนี้ที่หักไว้ (เลขที่ = ใบสำคัญจ่าย)
  "พิมพ์ 50 ทวิ" พิมพ์ฉบับที่ 1 (แนบแบบแสดงรายการภาษี) และฉบับที่ 2 (เก็บเป็นหลักฐาน): ผู้มีหน้าที่หัก (ชื่อ เลขประจำตัว 13 หลัก ที่อยู่ร้าน),
  ผู้ถูกหัก (ชื่อ เลขประจำตัว ที่อยู่จากข้อมูลผู้ขาย ค่าใช้จ่ายที่ชื่อผู้รับเงินไม่ตรงกับผู้ขายเว้นช่องที่อยู่ให้เขียน), ลำดับที่และติ๊กแบบ (4) ภ.ง.ด.3 หรือ (7) ภ.ง.ด.53,
  ตารางประเภทเงินได้ 1–6 ลงที่ข้อ 5 (ตามคำสั่งกรมสรรพากรที่ออกตามมาตรา 3 เตรส) พร้อมชื่อเงินได้ตามอัตรา (1% ค่าขนส่ง, 2% ค่าโฆษณา,
  3% ค่าบริการ / ค่าจ้างทำของ, 5% ค่าเช่า), วันที่จ่าย, จำนวนเงินที่จ่าย (ฐาน), ภาษีที่หัก, ตัวอักษร, กองทุน (ว่าง), ติ๊ก "(1) หัก ณ ที่จ่าย", คำเตือน,
  ช่องลงชื่อผู้จ่ายเงิน ลงวันที่วันที่จ่าย เลขที่ MA-WH… ออกตอนพิมพ์ครั้งแรกเหมือนเดิม ระบบเดิมพิมพ์ฉบับเดียวไม่มีส่วนเหล่านี้และลงวันที่ของรายการ
  ออกได้เมื่อจ่ายแล้วเท่านั้น ("ยังไม่ได้จ่ายเงิน — ออก 50 ทวิ ได้หลังจ่าย") ข้อความในแบบเขียนตามแบบฟอร์มของกรมสรรพากร **ให้ผู้ทำบัญชีตรวจอีกครั้ง**
  โดยเฉพาะการลงประเภทเงินได้ข้อ 5 สำหรับผู้รับเงินที่เป็นบุคคลธรรมดา (ค่าเช่าหรือค่าวิชาชีพของบุคคลอาจต้องลงข้อ 6 / มาตรา 40 (5), (6))
- ยังไม่ทำ (บันทึกไว้): ภาษีหัก ณ ที่จ่ายของการจ่ายเจ้าหนี้ยังไม่อยู่ในงบการเงิน / ผังบัญชี (ภาษีหัก ณ ที่จ่ายค้างนำส่ง) ซึ่งยังนับจากค่าใช้จ่ายตามระบบเดิม
  (งาน 3.6/3.7 บัญชี) และยังไม่มีการพิมพ์ใบแนบ ภ.ง.ด.3 / 53

## ข้อค้นพบจากเฟส 3 งาน 3.5 (รับชำระ)

คำตอบของเจ้าของโปรเจกต์: R2 = ก, R8-ก = ค / F3 = ก, R8-ข = ก และคำตอบงาน 3.5 วันที่ 2026-10-25 ใน [PHASE3-QUESTIONS.md](PHASE3-QUESTIONS.md)

- **รับเงินทุกครั้งได้ใบเสร็จทันที ทั้งสองทาง** (R2): ระบบเดิมรับเงินในหน้าต่างการขาย (รับชำระ, ชำระเงินตอนสร้างการขายใหม่) ไม่ออกเลข
  ต้องไปกด "สร้างใบเสร็จรับเงิน" ที่ 4.3 ภายหลัง ส่วนหน้ารับชำระเงินลูกหนี้ออกเลขทันที ระบบใหม่ออกเลข MA-RE… ทันทีทุกทาง
  ประวัติการใช้งานบอก "· ใบเสร็จ MA-RE…" ทั้งสองทาง (หน้ารับชำระเงินลูกหนี้เดิมเขียนประวัติก่อนได้เลข) และการขายใหม่ที่ชำระทันทีมีประวัติการรับเงินแล้ว
  (ระบบเดิมไม่มี) หลังรับเงินในหน้าต่างการขายเปิดหน้าต่างใบเสร็จให้พิมพ์ (แบบเดียวกับ "รับชำระและออกใบเสร็จ" ของ 4.3) แทนการ์ด "บันทึกข้อมูลสำเร็จ"
  การรับเงินเก่าที่ยังไม่มีเลข (ข้อมูลก่อน 3.5) ยังกด "สร้างใบเสร็จรับเงิน" ได้เหมือนเดิม (S13) ไม่ออกเลขย้อนหลังให้อัตโนมัติ เพราะเลขจะไม่เรียงตามวันที่รับเงิน
  (S151 แทน S01, S152 แทน S20, S153 แทน S26, S155 แทน S83, S156)
- **แบ่งจ่ายหลายวิธีหลายบิล** (R8-ข): ระบบเดิมเก็บวิธีชำระทั้งก้อนของการรับเงินครั้งนั้นซ้ำไว้ทุกบิล และใช้วิธีที่ยอดมากที่สุดเป็นวิธีของทุกบิล
  รายงานประจำวันจึงนับเงินซ้ำ (S21: เงินสด 10,000 แทน 5,000) ระบบใหม่แบ่งเงินแต่ละวิธีให้แต่ละบิล บิลเก่าก่อน วิธีตามลำดับที่ใส่
  การรับเงินของแต่ละบิลเก็บเฉพาะส่วนของตัวเอง (ยอดรวมของการรับเงินครั้งนั้นยังอยู่ใน `payTotal` / `payBills`)
  ใบเสร็จใบเดียวรวมทุกบิลแสดงวิธีชำระของทุกบิลรวมกัน ถ้าเลือก "แยกใบเสร็จตามบิล" (เก็บไว้ตามคำตอบ) ใบเสร็จแต่ละใบแสดงส่วนของบิลนั้น
  ซึ่งรวมได้เท่ายอดของใบ (ระบบเดิมแต่ละใบพิมพ์เงินสดทั้งก้อน 3,304.10 ใน S25) ข้อมูลที่บันทึกก่อน 3.5 รายงานประจำวันแบ่งตามสัดส่วนให้
  และใบเสร็จรวมแสดงตามเดิม ไม่แก้ข้อมูลเก่า (S154 แทน S21, S145, S156)
- **ค่าธรรมเนียมบัตร** (F3 = ก และคำตอบ 2026-10-25): ไม่ใช่รายได้ ไม่คิด VAT ยอดขายและเงินที่นับให้การขายยังเป็นยอดตามใบตัดสต็อก
  ใบเสร็จแสดงบรรทัดบัตรเป็นยอดที่รูด แล้ว "ยอดตามใบตัดสต็อก" + "ค่าธรรมเนียมบัตรเครดิต 3%" = ยอดรับครั้งนี้ (ตัวอักษรเป็นยอดที่รูด)
  หน้ารับชำระเงินลูกหนี้มีช่อง "ชาร์จเพิ่ม (%)" ของบัตรแล้ว (ระบบเดิมมีแค่ในหน้าต่างการขาย) ค่าธรรมเนียมอยู่กับเงินบัตรของบิลที่ได้เงินบัตร
  รายงานประจำวันบอกค่าธรรมเนียมบัตรที่ลูกค้าจ่ายเพิ่มของวัน (ไม่รวมในยอดบัตร) ให้ผู้ทำบัญชีใช้หักกับค่าธรรมเนียมที่ธนาคารเก็บ
  ยังรอผู้ทำบัญชียืนยันเรื่อง VAT (F3) ถ้าต้องเสีย VAT จะเปลี่ยนเป็นข้อ ข (S153, S156)
- **เงินคืนตามใบลดหนี้** (ต่อจาก 3.3): รายงานประจำวันแสดง "คืนเงินลูกค้าตามใบลดหนี้" ของวันที่ใบลดหนี้มีผล และเงินสดของปี (สุขภาพการเงิน) หักเงินที่คืนแล้ว (S156)
- ข้อสังเกตที่ยังไม่แก้: หน้าต่างใบเสร็จแบบเดิม (`#mReceiptEdit`) บนมือถือยังมีปุ่ม "สร้างใบใหม่" ในเมนู ⋯ ที่สร้างใบเสร็จแบบเดิมได้ขณะเปิดระบบขายแบบใหม่
  (บนคอมพิวเตอร์ถูกซ่อน) ไม่กระทบเลขใบเสร็จ (ได้ MA-RE… จากตัวนับเดียวกัน) จะแก้พร้อมงานหน้าจอเฟส 4,
  ข้อมูลทดลองที่ระบบสร้าง (55.js) กรณี "ยังไม่ออกใบเสร็จ" จะได้เลขแล้ว (ระบบจริงไม่สร้างข้อมูลทดลอง A1)
- **ข้อความใหม่ที่รอยืนยัน** (3.5): "ยอดตามใบตัดสต็อก", "ค่าธรรมเนียมบัตรเครดิต X%" / "ค่าธรรมเนียมบัตรเดบิต X%", "ค่าธรรมเนียมบัตร X% ฿… — ยอดที่ต้องรูดรวม ฿…"

## ข้อค้นพบจากเฟส 3 งาน 3.6 (สต๊อกและต้นทุน FIFO)

คำตอบของเจ้าของโปรเจกต์: R9-ก = ก, R9-ข = จ, R10-ก/ข/ค = ก, R10-ง = ค (F4), R11 = ก และคำตอบงาน 3.6 วันที่ 2026-10-25 ใน [PHASE3-QUESTIONS.md](PHASE3-QUESTIONS.md)
โค้ดอยู่ที่ `frontend/js/59-stock-fifo.js` (ต้นทุนยังคิดที่หน้าจอด้วยบัญชี FIFO เดิม `09.js` การตรวจซ้ำที่ server อยู่ในงาน 3.9 เหมือน 3.3–3.5)

- **ขายเกินของที่มีได้เฉพาะเจ้าของหรือผู้มีสิทธิ์อนุมัติ** (R9-ข = จ, คำตอบ "ใช้สิทธิ์อนุมัติที่มีอยู่"): ระบบเดิมใครตัดสต็อกได้ก็กด "ตัดสต็อก (ยอมติดลบ)" ได้
  ระบบใหม่ต้องเป็นเจ้าของ หรือพนักงานที่มีสิทธิ์อนุมัติเอกสารอย่างน้อยหนึ่งประเภท (ไม่เพิ่มช่องสิทธิ์ใหม่ จำนวนสิทธิ์ 68 ไม่เปลี่ยน)
  ใช้กับการขาย ฉบับแก้ไขที่ตัดเพิ่ม การเปลี่ยนสินค้าตามใบเคลมลูกค้า และการยกเลิกใบโอนที่ทำให้ปลายทางติดลบ คนอื่นได้ข้อความ
  "อะไหล่ N รายการมีไม่พอ — ตัดสต็อกติดลบได้เฉพาะเจ้าของหรือผู้มีสิทธิ์อนุมัติเอกสาร" และไม่มีอะไรถูกบันทึก
  การอนุมัติใบเบิก/ใบเคลมที่ของไม่พอทำได้โดยผู้อนุมัติของเอกสารนั้นอยู่แล้ว ต้นทุนของส่วนที่ขายเกินคิดชั่วคราวที่ทุนในทะเบียน แล้วแก้ย้อนหลังเมื่อของเข้า (R9-ก เหมือนเดิม) (S160)
- **ทุนในทะเบียน = ทุนเฉลี่ยของที่เหลือ** (F4): ระบบเดิมแทนด้วยราคาซื้อล่าสุด (S30: 850 → 870) ระบบใหม่ปรับทุกครั้งที่สต๊อกเคลื่อนไหว
  เป็นทุนเฉลี่ยของล็อต FIFO ที่เหลือ (ทุกสาขา ปัดเป็นสตางค์) ของหมดแล้วคงค่าล่าสุด ราคาขาย A/B/C ไม่เปลี่ยนเอง (S30: 19 × 850 + 10 × 870 → 856.90)
  สิ่งที่ใช้ทุนนี้: ต้นทุนชั่วคราวของการขายเกิน, ล็อตของของเกินจากการตรวจนับ, ของที่รับจากคลังกลาง, ราคาตั้งต้นของบรรทัดใบรับสินค้า (S157 แทน S30, S159 แทน S36)
- **ของขาด ของเกิน และการเบิกใช้ลงบัญชีจากเอกสารสต๊อก** (R10-ก/ข/ค, คำตอบ "คิดจากเอกสารสต๊อก"): ระบบเดิมไม่ลงที่ไหนเลย (ข้อ 10)
  ระบบใหม่ไม่สร้างรายการในทะเบียนรายจ่าย แต่อ่านจากบัญชี FIFO ทุกครั้งที่ทำรายงาน ตามวันที่สต๊อกเคลื่อนไหว: ของขาดของใบตรวจนับ = ค่าใช้จ่าย
  "สินค้าขาดจากการตรวจนับ" ตามทุน FIFO, ของเกิน = รายได้อื่นตามทุนในทะเบียน (แยกบรรทัด ไม่หักกลบกัน), ใบเบิก = ค่าใช้จ่ายตามหมวดที่เลือกในใบ
  (ช่องใหม่ "หมวดค่าใช้จ่าย" ข้างแผนก ตั้งต้น "ค่าซ่อมแซมและบำรุงรักษา") ยกเลิกเอกสารแล้วยอดหายเอง ต้นทุนชั่วคราวตามการแก้ย้อนหลัง
  ขึ้นในงบกำไรขาดทุน (ค่าใช้จ่ายของใบเบิกอยู่ใน "6000 ค่าใช้จ่ายในการขายและบริหาร", ของขาดและรายได้อื่นมีบรรทัดของตัวเองเมื่อมียอด),
  กำไรรายเดือน อันดับค่าใช้จ่าย และงบทดลอง (ของขาดใช้บัญชีของหมวด "ค่าใช้จ่ายเบ็ดเตล็ด" 6190 รายได้อื่น 4030) ไม่กระทบเงินสด เจ้าหนี้ และใบสำคัญจ่าย
  ใบตรวจนับ/ใบเบิกที่ตัดสต๊อกแล้วบอก "ลงบัญชีตามทุน FIFO: …" (S158 แทน S33, S159 แทน S36, S164 แทน S66, S161)
- **ขายของที่ขาดให้ผู้รับผิดชอบ** (R10-ก): ใบตรวจนับที่อนุมัติแล้วมีปุ่ม "เปิดใบขายให้ผู้รับผิดชอบ" เปิดการขายใหม่พร้อมรายการที่ขาด (อ้างอิงเลขใบตรวจนับ)
  เลือกลูกค้า (ผู้รับผิดชอบต้องมีในทะเบียนลูกค้า) แล้วบันทึกแบบการขายปกติ (มี VAT) ตอนบันทึก ของที่ขาดคืนให้ใบตรวจนับก่อนแล้วการขายตัดตาม FIFO
  สต๊อกจึงไม่ถูกตัดซ้ำ และต้นทุนย้ายจากค่าใช้จ่ายสินค้าขาดไปเป็นต้นทุนขาย ยกเลิกการขายนั้นแล้วของกลับเป็นของขาด ระหว่างที่การขายยังอยู่ ยกเลิกใบตรวจนับไม่ได้
  ข้อจำกัด: ฉบับแก้ไขหรือใบลดหนี้ที่คืนสินค้าของการขายนั้นคืนของเข้าสต๊อกเหมือนการขายทั่วไป (S161)
- **ของจากคลังกลาง** (R11 = ก, ข้อ 49, 64): ProX ออนไลน์รับของแล้วมีรายการเคลื่อนไหวและล็อต FIFO ตามทุนในทะเบียน (ระบบเดิมเพิ่มแค่จำนวน)
  แฟรนไชส์รายการเคลื่อนไหวเก็บทุนในทะเบียนของสาขา (เดิม 0) และสินค้าที่สาขายังไม่มีต้องกรอกทุนต่อหน่วยก่อนรับ (เดิมสร้างด้วยทุน 0 และแก้ไม่ได้อีก)
  หมวด "ไส้กรอง" ของสินค้าใหม่จาก ProX ยังเหมือนเดิม (S162 แทน S125, S114, S163)
- **รายการเคลื่อนไหวสต๊อก** (ข้อ 9): การ์ดสินค้าและรายงานการเคลื่อนไหวสินค้าแสดงของออกเป็นค่าลบสีแดงทุกประเภท (เดิมใบเบิกและใบเคลมขึ้น "+")
  และคอลัมน์ "ทุนต่อหน่วย" จากบัญชี FIFO ข้อมูลที่เก็บไม่เปลี่ยน (ต้นทุนจริงอยู่ในบัญชี FIFO ซึ่งแก้ย้อนหลังได้ จึงไม่เก็บซ้ำในรายการเคลื่อนไหว) (S161)
- **ข้อความใหม่ที่รอยืนยัน** (3.6): "อะไหล่ N รายการมีไม่พอ — ตัดสต็อกติดลบได้เฉพาะเจ้าของหรือผู้มีสิทธิ์อนุมัติเอกสาร", "หมวดค่าใช้จ่าย",
  "ลงบัญชีตามทุน FIFO: ค่าใช้จ่ายสินค้าขาด … บาท · รายได้อื่น (สินค้าเกิน) … บาท", "ลงบัญชีตามทุน FIFO: ค่าใช้จ่ายหมวด … … บาท",
  "เปิดใบขายให้ผู้รับผิดชอบ", "ขายของที่ขาดให้ผู้รับผิดชอบแล้ว: …", "ดึงของที่ขาดจากใบตรวจนับ … แล้ว — เลือกลูกค้า (ผู้รับผิดชอบ) แล้วบันทึกการขาย",
  "ไม่มีของขาดที่ยังไม่ได้เปิดใบขาย", "ใบตรวจนับ … มีใบขายของที่ขาด … — ยกเลิกใบขายก่อน", ประวัติการใช้งาน "ขายของที่ขาดให้ผู้รับผิดชอบ"
  ("… · ใบตัดสต็อก … · AC-215 × 2", "ยกเลิกใบตัดสต็อก … · กลับเป็นของขาด …"), รายการเคลื่อนไหว "ขายของที่ขาดให้ผู้รับผิดชอบ · ใบตัดสต็อก …",
  "ยกเลิกใบตัดสต็อก … · กลับเป็นของขาด", "รับของจากคลังกลาง ProX · คำขอ #…", งบการเงิน "สินค้าขาดจากการตรวจนับ", "บวก รายได้อื่น (สินค้าเกินจากการตรวจนับ)",
  "ทุนต่อหน่วย", "ทุนของสินค้าใหม่", "สินค้า N รายการยังไม่มีในทะเบียนของสาขา — กรอกทุนต่อหน่วย (ใช้เป็นต้นทุน FIFO และทุนในทะเบียน)",
  "รับของเข้าสต๊อก" / "ยังไม่รับ", "กรอกทุนต่อหน่วยของสินค้าใหม่ให้ครบทุกรายการ"
- ให้ผู้ทำบัญชีดู: ของขาดลงบัญชี 6190 (หรือควรเป็นต้นทุนขาย), ของเกินลงรายได้อื่น 4030 ตามทุนในทะเบียน, งบทดลองยังเป็นแบบประมาณการเหมือนเดิม

## ข้อค้นพบจากเฟส 3 งาน 3.7 (เงินเดือนและประกันสังคม)

คำตอบของเจ้าของโปรเจกต์: R12 (ยืนยัน + ค), R13-ก/ข/ง/จ = ก, F5 = ค, X2 = ก และคำตอบงาน 3.7 วันที่ 2026-10-25 ใน [PHASE3-QUESTIONS.md](PHASE3-QUESTIONS.md)
โค้ดอยู่ที่ `frontend/js/60-payroll.js` (ภาษีเงินเดือนพนักงาน R13-ฉ / F6 อยู่ในงาน 3.8 รอวิธีคำนวณจากผู้ทำบัญชี, การตรวจซ้ำที่ server อยู่ในงาน 3.9)

- **ประกันสังคมตามกฎหมาย** (R12): ฐาน = เงินเดือน + เงินได้ประจำ (ช่องใหม่ "เงินได้ประจำ (บาท/เดือน)" ในฟอร์มพนักงาน) ไม่รวมค่าล่วงเวลาและเงินพิเศษ
  ขั้นต่ำ 1,650 เพดานตามกฎหมายรายเดือน (15,000 → ม.ค. 2569 17,500 → 2572 20,000 → 2575 23,000 ตามที่ประกาศไว้ — ตรวจกับประกาศจริงอีกครั้งก่อนถึงปี)
  5% ทั้งสองฝ่าย ปัดเป็นบาท (ระบบเดิม: 15,000 / 750 และนับค่าล่วงเวลา/เงินพิเศษคงที่ทุกเดือน) ร้านตั้งค่าเองได้ที่เมนู 10 (R12 = ค):
  ระบบถามก่อน ("อัตราประกันสังคมต่างจากกฎหมาย") ใช้ตั้งแต่เดือนที่ตั้ง บอกไว้ข้างหัวข้อ "ตั้งค่าการทำงานของระบบ" และลงประวัติการใช้งาน (ประเภทใหม่ "ตั้งค่าองค์กร")
  กรอกค่าตามกฎหมายกลับคือกลับไปใช้ตามกฎหมาย ช่องเดิม `DB.shop.ssoRate…` ไม่ถูกอ่านและไม่ถูกแก้ (S168, S173)
- **งวดเงินเดือน** (R13, F5): บันทึกแล้วได้รายจ่าย 2 รายการเหมือนเดิม ลงวันที่สิ้นเดือน แต่เป็นค้างจ่าย (หรือเลือก "จ่ายแล้ว" ตอนบันทึก)
  แล้วกด "จ่ายเงินเดือน" (จ่ายสุทธิหลังหักประกันสังคม) และ "นำส่งประกันสังคม" (ลูกจ้าง + นายจ้าง) แยกกัน เลือกวันที่และวิธีจ่าย ได้ใบสำคัญจ่าย MA-PV
  (ตามคำตอบ 3.4) ใบสำคัญจ่ายเงินเดือนแสดงรายการหักเงินสมทบส่วนลูกจ้าง งวดที่บันทึกแล้วบันทึกซ้ำไม่ได้ ต้องยกเลิกก่อน
  ยกเลิกได้ทุกเมื่อแม้จ่ายแล้ว ต้องใส่เหตุผล รายจ่ายของงวดถูกลบ งวดที่ยกเลิกเก็บเลขรายจ่ายและใบสำคัญจ่ายเดิมไว้และแสดงในประวัติ
  ค่าล่วงเวลาและเงินพิเศษกรอกในหน้าจ่ายเงินเดือนของเดือนนั้น (ช่องคงที่ในฟอร์มพนักงานถูกซ่อน ค่าที่เก็บไว้เดิมไม่ถูกใช้)
  เริ่มงาน/ลาออกกลางเดือน = เงินเดือน (และเงินได้ประจำ) ÷ 30 × จำนวนวันตามปฏิทินที่ทำงาน ฐานประกันสังคม = ค่าจ้างที่จ่ายจริง (ไม่ต่ำกว่า 1,650)
  สลิปเงินเดือนรายคนพิมพ์จากหน้าจ่ายเงินเดือน บันทึก จ่าย และยกเลิกได้เฉพาะเจ้าของหรือผู้มีสิทธิ์ "บันทึกค่าใช้จ่าย" รายจ่ายของงวดจ่าย แก้ และลบได้ผ่านงวดเท่านั้น
  ข้อมูลอยู่ที่ `DB.payroll` (server เก็บหนึ่งงวดหนึ่งแถว) (S165 แทน S40, S172)
- **รายงานใช้งวดที่บันทึกเท่านั้น** (X2 และคำตอบ "เฉพาะงวดที่บันทึก"): ระบบเดิมนับเงินเดือนสองครั้ง (ประมาณการจากรายชื่อพนักงานทุกเดือน
  + รายจ่ายเงินเดือนที่บันทึก) ระบบใหม่ตัดประมาณการออกทุกที่ งบกำไรขาดทุน กำไรรายเดือน อันดับค่าใช้จ่าย เงินสด และงบทดลองใช้รายจ่ายของงวดที่บันทึก

## ข้อค้นพบจากเฟส 3 งาน 3.8 (ภาษีเงินเดือนพนักงาน ภ.ง.ด.1)

คำตอบของเจ้าของโปรเจกต์: R13-ฉ = ข, F6-ก = ข (ผู้ทำบัญชีกำหนดวิธีคำนวณ — ยังไม่ได้รายละเอียด), F6-ข = ก และคำตอบงาน 3.8 วันที่ 2026-10-25

ระบบเดิมไม่มีภาษีเงินเดือนพนักงานเลย โค้ดอยู่ที่ `frontend/js/60-payroll.js` (50 ทวิ ใช้แบบฟอร์มเดียวกับงาน 3.4 ใน `52.js`)

- **ภาษีที่หักกรอกเองรายงวด**: คอลัมน์ "หักภาษี ณ ที่จ่าย" ในหน้าจ่ายเงินเดือน (ช่องกรอกแบบเดียวกับค่าล่วงเวลา) ระบบยังไม่คำนวณเอง
  ห้ามเกินรายได้หลังหักประกันสังคม ("ภาษีหัก ณ ที่จ่ายของ … ต้องไม่เกินรายได้หลังหักประกันสังคม (… บาท)") เก็บในงวด `lines[].tax`, `totals.tax`
  ค่าใช้จ่ายเงินเดือนยังเป็นยอดรวมรายได้ จ่ายพนักงานสุทธิหลังหักประกันสังคมและภาษี (ใบสำคัญจ่ายเงินเดือนมีรายการหักภาษี) สลิปมีรายการหัก "ภาษีเงินได้หัก ณ ที่จ่าย"
- **นำส่ง ภ.ง.ด.1** (แบบเดียวกับประกันสังคม): ภาษีถือว่าหักตอนจ่ายเงินเดือน ปุ่ม "นำส่ง ภ.ง.ด.1" จึงขึ้นหลังจ่ายเงินเดือนแล้ว
  (ก่อนหน้านั้นบอก "ภาษีหัก ณ ที่จ่าย … บาท — นำส่งหลังจ่ายเงินเดือน") เลือกวันที่และวิธีจ่าย ได้ใบสำคัญจ่าย MA-PV จ่ายให้กรมสรรพากร
  เก็บที่งวด `taxRemit` (ไม่ใช่รายจ่ายใหม่ เพราะภาษีเป็นส่วนหนึ่งของเงินเดือนที่ลงค่าใช้จ่ายแล้ว) ประวัติการจ่ายเงินเดือนมีแถวการนำส่งของแต่ละงวด
  ยกเลิกงวดหลังนำส่งแล้วได้ ข้อความและประวัติบอกเลขใบสำคัญจ่ายของการนำส่ง เงินสดและงบทดลอง: ภาษีที่หักจากเงินเดือนที่จ่ายแล้วแต่ยังไม่นำส่ง
  อยู่ในเงินสด และขึ้นเป็นภาษีหัก ณ ที่จ่ายค้างนำส่ง (บัญชีเดียวกับ ภ.ง.ด.3/53) จนกดนำส่ง (S174)
- **รายงานภาษี**: บรรทัด "ภาษีเงินเดือนหัก ณ ที่จ่ายที่ต้องนำส่ง (ภ.ง.ด.1) … · นับตามวันที่จ่ายเงินเดือน" ขึ้นเฉพาะเดือนที่มีภาษี
  (นับตามวันที่จ่าย เหมือนคำตอบ 3.4 เรื่อง ภ.ง.ด.3/53 ส่วน "ฐานเงินเดือนสำหรับ ภ.ง.ด.1" และตารางเงินเดือนยังเป็นงวดของเดือนนั้นตาม X2)
  ตารางเงินเดือนมีคอลัมน์ "ภาษีหัก ณ ที่จ่าย" และปุ่ม "พิมพ์สรุป ภ.ง.ด.1" (ผู้มีเงินได้ทุกคนที่จ่ายในเดือนนั้น เลขบัตรประชาชน วันที่จ่าย
  เงินได้ ภาษี เงื่อนไข 1 = หัก ณ ที่จ่าย และสถานะการนำส่งของแต่ละงวด) — เป็นสรุปให้ผู้ทำบัญชีกรอกแบบ ไม่ใช่ใบแนบ ภ.ง.ด.1 ตามแบบสรรพากร
- **50 ทวิ ประจำปีของพนักงาน** (F6-ข): ปุ่ม "พิมพ์ 50 ทวิ ประจำปีของพนักงาน" ในรายงานภาษี พิมพ์ของทุกคนที่ได้รับเงินเดือนในปีของเดือนที่เลือก
  (นับตามวันที่จ่าย) แบบเดียวกับ 50 ทวิ ของงาน 3.4 ฉบับที่ 1 และ 2: ติ๊ก (1) ภ.ง.ด.1ก, เงินได้ประเภท 1 "ปี 2569", ยอดเงินได้และภาษีทั้งปี,
  เงินสมทบประกันสังคมของลูกจ้างในช่อง "กองทุนประกันสังคม", ลำดับที่ตามรหัสพนักงาน, เลขผู้เสียภาษี = เลขบัตรประชาชน, ที่อยู่จากช่องใหม่
  "ที่อยู่ (สำหรับ 50 ทวิ)" ในฟอร์มพนักงาน (อยู่แถวเดียวกับเงินเดือน แทนที่ช่องค่าล่วงเวลา/เงินพิเศษที่ซ่อนไปในงาน 3.7 ฟอร์มจึงไม่สูงขึ้น)
  เลขที่หนังสือรับรองใช้ชุด MA-WH… เดียวกับ 50 ทวิ ของผู้ขาย ออกตอนพิมพ์ครั้งแรกและเก็บที่พนักงานรายปี (`emp.cert50`) พิมพ์ซ้ำหรือบันทึกฟอร์มพนักงานแล้วเลขเดิม
  พิมพ์ระหว่างปีได้ (เช่น พนักงานลาออก) ยอดเป็นยอดถึงวันที่พิมพ์ ออกได้เฉพาะเจ้าของหรือผู้มีสิทธิ์ "บันทึกค่าใช้จ่าย" (S175)
- **ข้อความใหม่ที่รอยืนยัน** (3.8): "หักภาษี ณ ที่จ่าย" (หัวคอลัมน์), "ภาษีหัก ณ ที่จ่าย …" (ช่องกรอก), ข้อความห้ามเกินรายได้,

  "นำส่ง ภ.ง.ด.1 แล้ว …", "บันทึกนำส่ง ภ.ง.ด.1 … แล้ว · ใบสำคัญจ่าย …", แถวประวัติ "นำส่งภาษีหัก ณ ที่จ่าย (ภ.ง.ด.1) งวด …" / "รอจ่ายเงินเดือน",
  ใบสำคัญจ่ายของการนำส่ง, บรรทัดในรายงานภาษี, "พิมพ์สรุป ภ.ง.ด.1" และแผ่นสรุป, "พิมพ์ 50 ทวิ ประจำปีของพนักงาน",
  "ปี … / เดือน … ยังไม่มีเงินเดือนที่จ่ายแล้ว", "บัญชีนี้ไม่มีสิทธิ์ออก 50 ทวิ ของพนักงาน (ต้องมีสิทธิ์บันทึกค่าใช้จ่าย)", "ที่อยู่ (สำหรับ 50 ทวิ)"
- ให้ผู้ทำบัญชีดู: วิธีคำนวณภาษีเงินเดือน (เมื่อส่งมาจะเพิ่มให้ระบบเติมยอดให้), ภ.ง.ด.1 นับตามวันที่จ่ายเงินเดือน,

  หน้าจอ: หน้าจ่ายเงินเดือน (06.4) และตารางเงินเดือนในรายงานภาษีของคนที่ไม่มีสิทธิ์ขึ้นข้อความแทนตาราง ปุ่มบันทึก พิมพ์ใบจ่ายเงินเดือน สลิป
  สรุป ภ.ง.ด.1 ตอบข้อความเดียวกัน การบันทึกเงินเดือนต้องมีทั้ง "บันทึกค่าใช้จ่าย" และสิทธิ์ดูเงินเดือน (S176 แทน S41, S177 แทน S47, S178)
- **ไฟล์สำรองทั้งร้านเป็นของเจ้าของ**: อ่านจุดสำรองและสำเนาข้อมูลทั้งชุด (`garage.v22.*`) ได้เฉพาะเจ้าของ HQ หัวหน้าสาขา (คนอื่นได้ 403)
  การสร้างจุดสำรองอัตโนมัติยังทำได้ทุกคน (server คัดลอกจากข้อมูลของตัวเอง) ปุ่ม "ส่งออกไฟล์สำรองทั้งระบบ" และ "กู้คืนข้อมูลจากจุดสำรองที่เลือก"
  ของคนอื่นตอบ "ส่งออกไฟล์สำรองทั้งร้านได้เฉพาะเจ้าของร้าน" / "กู้คืนจากจุดสำรองได้เฉพาะเจ้าของร้าน" แม้มีสิทธิ์ส่งออกหรือสำรองข้อมูล
  (ไฟล์รายชื่อพนักงาน CSV ของระบบเดิมไม่มีเลขบัตรและเงินเดือนอยู่แล้ว)
- **ทุน (ส่วนที่ 2, F7 = ก)**: คนที่เห็นทุนได้ = เจ้าของ HQ หัวหน้าสาขา หรือพนักงานที่มี "แสดงต้นทุน" (`stock.cost`)
  หรือมีงานที่เห็นราคาซื้อ (`COST_JOBS` ใน `server/lib/visibility.ts`): ใบรับสินค้า (`sub.buyGr`) อนุมัติใบรับสินค้า (`apv.gr`) จ่ายเงินเจ้าหนี้ (`doc.payGr`)
  เจ้าหนี้ค้างจ่าย (`sub.acctAp`) และดูสรุปการเงิน (`doc.fin`, ผมเพิ่มเองเพราะงบกำไรขาดทุนแสดงต้นทุนขายและกำไรขั้นต้น **ขอเจ้าของยืนยัน**)
  ติ๊กงานเหล่านี้ในฟอร์มพนักงานแล้ว "แสดงต้นทุน" เปิดให้เองเมื่อบันทึก (ฟอร์มบอกไว้)
  **ผลเคลม**: เจ้าของตอบว่างานบันทึกผลเคลมต้องเห็นทุน แต่สิทธิ์ "เคลมสินค้า" (`sub.stkClaim`) อยู่ในชุดสิทธิ์ของช่าง
  ถ้านับเป็นงานที่เห็นทุน ช่างทุกคนจะเห็นทุน จึงทำแบบนี้แทน: เปิดใบเคลมได้เหมือนเดิม แต่ปุ่มบันทึกผลเคลม (รับคืน / ตีเสีย / หักยอด ยอดเริ่มต้นคือทุน)
  ต้องให้คนที่เห็นทุนกด **ขอเจ้าของยืนยัน**
  คนอื่น server ไม่ส่งทุนที่ไหนเลย (เป็น null): ทะเบียนสินค้า ล็อตและการตัดล็อต FIFO รายการเคลื่อนไหว ราคาซื้อและส่วนลดในใบรับสินค้า
  ต้นทุนในใบตัดสต็อก ใบโอน ใบเคลมลูกค้า ผลเคลมผู้ขาย (`result.amt`, `creditAmt`, `recvSummary`) แคตตาล็อกและใบขอของ ProX
  ต้นทุนขายในรายงานการย้ายระบบขาย และประวัติการใช้งานของใบรับสินค้าหรือที่มีคำว่า "ทุน"
  **server คิดทุนให้เมื่อคนที่ไม่เห็นทุนบันทึก** (`server/lib/costing.ts`): เบราว์เซอร์ของคนนั้นตัดล็อต FIFO ได้ถูก แต่ไม่รู้ทุน
  server จึงใส่ค่าที่เก็บไว้กลับก่อน แล้วคิดใหม่ตามกฎของระบบเดิม: การตัดล็อต = ทุนของล็อตนั้น (ติดลบ = ทุนในทะเบียน),
  ล็อตใหม่ = ทุนในทะเบียน (ยอดยกมา ของเกินจากใบตรวจนับ) หรือทุนของรายการรับเข้าจากใบรับสินค้า หรือทุนของรายการเคลื่อนไหวที่รับเข้า (ใบโอน ใบเคลม),
  รายการเคลื่อนไหว = ทุนของบรรทัดใบโอน/ใบเคลมลูกค้า (เคลมผู้ขาย = ทุนในทะเบียน อื่น ๆ = 0 เหมือนระบบเดิม),
  ต้นทุนของใบตัดสต็อก = ทุนเฉลี่ยที่ตัดได้ (ฉบับแก้ไขหักส่วนที่คืน), ทุนในทะเบียน = ทุนเฉลี่ยของล็อตที่เหลือ (เปลี่ยนเมื่อต่างเกิน 0.004 เหมือน 3.6)
  ทดสอบโดยให้ผู้จัดการ (EMP004 ปิดทุนและงานที่เห็นราคาซื้อ) ทำตาม S17 S16 S15 S12 S33 S32 S37 แล้วเทียบทุนทุกช่องที่ server เก็บกับเฉลยของระบบเดิม (S179, S181–S186)
  ข้อจำกัดที่ยอมรับ: ใบเคลมลูกค้าที่เปลี่ยนสินค้าคิดตามกฎเดียวกันแต่ไม่มีเฉลย FIFO ให้เทียบ; ถ้าบันทึกครั้งเดียวรับสินค้าตัวเดียวกันเข้าจากหลายเอกสาร
  ล็อตรับเข้าใช้ทุนของรายการแรกที่ตรงเลขเอกสาร; สินค้าใหม่ที่คนไม่เห็นทุนสร้างมีทุน 0 (เหมือนระบบเดิมเมื่อไม่กรอก); ของใหม่ของสาขาที่รับจากคลังกลาง
  (ต้องกรอกทุน, 3.6) และผลเคลมต้องให้คนที่เห็นทุนทำ
  หน้าจอของคนที่ไม่เห็นทุน: ทะเบียนสินค้าไม่มีช่องมูลค่าทุนในแถบสรุป (**ข้อ 13** ที่อนุมัติ: ระบบเดิมซ่อนด้วย `hidden` แต่ CSS ของช่องชนะ จึงยังเห็น),
  ฟอร์มสินค้าไม่มีราคาซื้อและกำไรต่อระดับราคา, การ์ดสินค้าไม่มีต้นทุนล่าสุด กำไรที่ระดับราคา B และคอลัมน์ทุน, ประวัติรับสินค้าและรายงานการเคลื่อนไหวไม่มีคอลัมน์ทุน,
  ใบตรวจนับและใบเบิกไม่มีบรรทัด "ลงบัญชีตามทุน FIFO", ใบเคลมลูกค้าที่เปลี่ยนสินค้าไม่บอกต้นทุน (ประวัติและข้อความ)
- **server ตรวจกติกาตอนบันทึก (ส่วนที่ 3)** (`server/lib/rules.ts`, เรียกหลังใส่ค่าที่ซ่อนกลับและคิดทุนแล้ว ก่อนเขียน): บันทึกที่หน้าจอไม่ยอมให้ทำ
  ถ้าเรียก API ตรงจะได้ 403 ไม่มีอะไรถูกเขียน (หน้าจอขึ้นข้อความเดิมของ T10 "บันทึกไม่สำเร็จ — บัญชีนี้ไม่มีสิทธิ์แก้ข้อมูลส่วนนี้ …")
  "เจ้าของ" ในข้อเหล่านี้ = ใครก็ตามที่หน้าจอถือว่าเป็นเจ้าของ (เจ้าของร้าน HQ หัวหน้าสาขา บัญชีพนักงานสาขาที่ไม่ได้ผูกพนักงาน)
  · งวดภาษี: ปิดงวดได้เฉพาะเจ้าของหรือผู้มีสิทธิ์ "ปิดงวดภาษี" (และแก้ได้แค่เพิ่มการปิด) เปิดงวดกลับได้เฉพาะเจ้าของ
  · เดือนที่ปิดงวดแล้ว: เอกสารที่มี VAT ลงวันที่ในเดือนนั้น (ใบเสร็จ ใบตัดสต็อก ใบรับสินค้า ค่าใช้จ่าย สินทรัพย์) แก้ส่วนที่มีผลต่อภาษี
    (วันที่ คู่ค้า เลขใบกำกับ รายการ ส่วนลด VAT ยอด) ยกเลิก ทำฉบับแก้ไข ปรับยอด (ยกเว้นของใบลดหนี้) ยกเลิกใบกำกับ ลบ หรือสร้างใหม่ไม่ได้
    แม้เป็นเจ้าของ (ต้องเปิดงวดกลับก่อน) รับเงิน จ่ายเงิน และออกใบกำกับเต็มรูปภายหลัง (T2-ก) ทำได้
  · ใบลดหนี้: ออกได้เฉพาะเจ้าของหรือผู้มีสิทธิ์ "ออกใบลดหนี้" ใบที่พนักงานออกต้องรออนุมัติ อนุมัติหรือไม่อนุมัติได้เฉพาะเจ้าของหรือผู้มีสิทธิ์อนุมัติใบกำกับภาษี
    รายการปรับลดของการขายที่อ้างใบลดหนี้ต้องมาจากใบลดหนี้ที่มีผลแล้ว (ใบเดียวกันในการบันทึกครั้งนั้นหรือที่เก็บไว้)
  · ไม่คิด VAT: ใบเสนอราคา ใบเสร็จ ใบตัดสต็อกของร้านที่จด VAT ที่เพิ่งไม่คิด VAT ต้องเป็นเจ้าของหรือผู้มีสิทธิ์ "เลือกไม่คิด VAT"
    (เหตุผลถามที่หน้าจอ server ไม่บังคับ เพราะข้อมูลตัวอย่างและข้อมูลเดิมมีเอกสารที่ไม่มีเหตุผล) เว้นแต่รับมาจากเอกสารต้นทาง (ใบเสนอราคา ใบเดิมที่แก้หรือคัดลอก การขายของใบเสร็จนั้น) เอกสารเดิมที่ไม่คิด VAT อยู่แล้วบันทึกต่อได้
  · ขายเกินของที่มี: การขาย ฉบับแก้ไข และการเปลี่ยนสินค้าตามใบเคลมลูกค้าที่ทำให้สินค้าติดลบ (หรือติดลบมากขึ้น) ต้องเป็นเจ้าของหรือผู้มีสิทธิ์อนุมัติเอกสาร
  · เงินเดือน: บันทึก จ่าย นำส่ง ยกเลิกงวด ต้องเป็นเจ้าของหรือมีทั้ง "บันทึกค่าใช้จ่าย" และสิทธิ์ดูเงินเดือน และเดือนหนึ่งมีงวดที่ไม่ยกเลิกได้งวดเดียว
  ทดสอบกฎทีละข้อด้วย `tests/db/rules.test.mjs` และทุกสถานการณ์ของระบบใหม่รันโดยเปิดกฎเหล่านี้
- **หน้าแรกไม่แสดงยอดเงินรอชำระ (ข้อ 42 ที่อนุมัติ)**: การ์ด "รอชำระ (ใบตัดสต็อก)" ของพนักงานที่ไม่มี "ดูยอดเงินและมูลค่าในหน้าแรก" (`doc.homeMoney`)
  แสดงจำนวนใบและใบค้างข้ามวัน ไม่มี "รวม ฿…" (S180 แทน S04, S176; พนักงานสาขาที่ผูกพนักงานก็เช่นกัน: S110, S118)
- **ข้อความใหม่ที่รอยืนยัน** (3.9): "บัญชีนี้ไม่มีสิทธิ์ดูเงินเดือน (ต้องมีสิทธิ์ดูสรุปการเงิน ภาษี และเงินเดือน หรือดูและแก้ไขข้อมูลพนักงาน)",
  "ส่งออกไฟล์สำรองทั้งร้านได้เฉพาะเจ้าของร้าน", "กู้คืนจากจุดสำรองได้เฉพาะเจ้าของร้าน",
  "มีสินค้าใหม่ N รายการที่ต้องกรอกทุน — ให้ผู้มีสิทธิ์เห็นต้นทุนรับของเข้าสต๊อก",
  "บันทึกผลเคลม (รับคืน / ตีเสีย / หักยอด) ต้องให้ผู้มีสิทธิ์เห็นต้นทุนเป็นผู้บันทึก",
  "งานที่เห็นราคาซื้อ (ใบรับสินค้า อนุมัติใบรับสินค้า จ่ายเงินเจ้าหนี้ เจ้าหนี้ค้างจ่าย ดูสรุปการเงิน) เปิด "แสดงต้นทุน" ให้เองเมื่อบันทึก"

## ต้นฉบับ v24 (2026-10-26)

เจ้าของโปรเจกต์ส่ง `DRIVEGO_TRIAL_v24.html` มาและอนุมัติให้ใช้เป็นต้นฉบับ (เฉลย) แทน v23 (แชต 2026-10-26)
v24 ต่างจาก v23 แค่ 21 บรรทัด ทั้งหมดเป็นเรื่องการแจกไฟล์ทดลอง ไม่แตะการขาย สต๊อก ภาษี เงินเดือน หรือสิทธิ์:

  เก็บแพ็กเกจในเบราว์เซอร์แล้วโหลดหน้าใหม่แทนการเปลี่ยนลิงก์ (`trialGo`, ให้มือถือที่เปิดไฟล์จากแชตเลือกแพ็กเกจได้)

## ข้อค้นพบจากเฟส 3 งาน 3.14 (ชื่อไฟล์ PDF)

คำตอบของเจ้าของโปรเจกต์: F9-ก = ข (ใช้หน้าพิมพ์ของเบราว์เซอร์เหมือนเดิม แต่ตั้งชื่อไฟล์ให้), F9-ข = ก และคำตอบ 14.1–14.4 ใน [PHASE3-QUESTIONS.md](PHASE3-QUESTIONS.md)

ที่พบตอนสำรวจ (รันระบบเดิม): การพิมพ์ทุกอย่างผ่าน `printDocs(html)` (03.js) ที่ใส่แผ่นลง `#printStage` แล้วเรียก `window.print()` อีก 80 ms ต่อมา
ไม่มีหน้าต่างใหม่หรือ iframe ชื่อไฟล์ PDF ที่เบราว์เซอร์เสนอมาจาก `document.title` ของหน้า ซึ่งระบบเดิมเป็น "ระบบบริหารงานอู่ซ่อมรถ"
(หรือ "<ชื่อพนักงาน> · ระบบบริหารงานอู่ซ่อมรถ" จาก `applyPerms`) ทุกไฟล์จึงชื่อเดียวกัน Chrome ถือส่วนหลังจุดสุดท้ายเป็นนามสกุลแล้วแทนที่
ชื่ออย่าง "หจก. บางมดขนส่ง" จึงถูกตัด ชื่อที่ตั้งจึงลงท้าย `.pdf` เสมอ

- **วิธีทำ** (`frontend/js/63-pdf-name.js`): ครอบ `window.printDocs` ชั้นนอกสุด (ตัวครอบของ 31.js 37.js 46.js 55.js เรียกผ่าน `window.printDocs` ตอนเรียก จึงผ่านตัวนี้ทุกครั้ง)
  หลังแผ่นพร้อมใน `#printStage` อ่านจากแผ่นที่พิมพ์ (ไม่ใช่ข้อมูลของแต่ละหน้า) แล้วตั้ง `document.title` ก่อนหน้าพิมพ์เปิด
  คืนชื่อเดิมเมื่อ `afterprint` เมื่อพิมพ์ครั้งถัดไป หรือครบ 1 นาที (เบราว์เซอร์ headless และมือถือบางรุ่นไม่ส่ง `afterprint`) ถ้าระหว่างนั้นชื่อหน้าต่างถูกเปลี่ยน (เช่น `applyPerms` ตอนสลับผู้ใช้) ใช้ชื่อใหม่นั้น
- **ประเภท** = หัวเอกสาร (`.dtitle`) ถึง " / " แรก ไม่เอาส่วนใน "(…)" เช่น "ใบเสนอราคา / ใบอนุมัติซ่อม" → ใบเสนอราคา, "ใบส่งมอบงาน / ใบเสร็จรับเงิน / ใบแจ้งหนี้" → ใบส่งมอบงาน,
  "งบทดลอง (Trial Balance)" → งบทดลอง ใบแบบย่อ 80 มม. และ 50 ทวิ ไม่มีกล่องหัวเอกสาร ใช้บรรทัดตัวหนาสุดท้ายของหัวกลางหน้า ("ใบกำกับภาษีอย่างย่อ / ใบตัดสต็อกขายสินค้า" → ใบกำกับภาษีอย่างย่อ)
- **เลขที่** = ช่อง "เลขที่" ที่พิมพ์ (ใบ 80 มม. และ 50 ทวิ: "เลขที่ X" ในเนื้อ) ยังไม่บันทึก ("(ยังไม่บันทึก)", "-", ว่าง) → "ร่าง"
- **คู่ค้า** = ตัวหนาแรกหลังป้าย ลูกค้า / ได้รับเงินจาก / ชื่อผู้ซื้อ / ผู้รับบริการ / เรียน / ผู้ขาย (/ ผู้รับเคลม) / จ่ายให้ / ผู้ถูกหักภาษี ณ ที่จ่าย / พนักงาน (ไม่เอารหัสพนักงาน)
  หรือช่อง "สาขาปลายทาง" (ใบโอน) ใบ 80 มม. ใช้บรรทัด "ลูกค้า …" "ลูกค้าทั่วไป (เงินสด)" / "ลูกค้าทั่วไป / ขายหน้าร้าน" → ลูกค้าทั่วไป
  เอกสารภายใน (ใบเบิก ใบตรวจนับ) ไม่มีป้ายเหล่านี้จึงไม่มีส่วนที่สาม
- **ยกเลิก**: ตราประทับ "ยกเลิกแล้ว" (`.dstamp` ลายน้ำ `.apvwm`) หรือ "— ยกเลิกแล้ว —" / ตัวหนา "ยกเลิกแล้ว" (ใบ 80 มม. ใบเสร็จของการขาย) → ต่อท้าย `_ยกเลิก`
- **เอกสารที่ไม่มีเลขที่แต่มีคู่ค้า** (สลิปเงินเดือน): `<ประเภท>_<งวด>_<คู่ค้า>` เช่น `สลิปเงินเดือน_2026-10_ศักดิ์ชัย มั่นคง.pdf`
- **รายงาน** (ไม่มีเลขที่และไม่มีคู่ค้า): `<ชื่อรายงาน>_<งวด>` ชื่อรายงานเต็ม (ไม่ตัดที่ " / " อักษร "/" เป็นช่องว่างเหมือนไฟล์ Excel ไม่เอา "(…)") งวดมาจากช่อง "งวด…" / "ช่วง…" / "ปี…" ก่อน ถ้าไม่มี หาคำว่า "เดือน/งวด <เดือน> <ปี>" หรือ "ปีบัญชี … <ปี>"
  ในเนื้อรายงาน (รายงานภาษี งบทดลอง งบการเงิน) สุดท้ายใช้ "ณ วันที่" / "วันที่พิมพ์" / "วันที่ส่งออก" วันที่เป็นแบบ ISO ค.ศ. เหมือนไฟล์ Excel (`2026-10-13`, เดือน `2026-10`, ปี `2026`)
  รายการเอกสาร (ปุ่ม "พิมพ์รายการ") ขึ้นต้น "รายการ" เช่น `รายการใบเสนอราคา ใบอนุมัติซ่อม_2026-10-13.pdf` เพื่อไม่ให้ชื่อซ้ำกับตัวเอกสาร
  ทะเบียน 24 หน้าที่มีปุ่ม PDF ใช้ชื่อหัวหน้า เช่น `ใบเสนอราคา ใบอนุมัติซ่อม_2026-10-13.pdf`
- **พิมพ์หลายใบ** (เลขที่หรือคู่ค้าต่างกันมากกว่าหนึ่ง): `<ประเภท>_<งวดหรือวันที่>_ทุกคน` เมื่อทุกใบเป็นของพนักงาน (สลิปทุกคน, 50 ทวิ ประจำปีของพนักงาน) ไม่เช่นนั้น `_<n> ใบ` (ใบเสร็จทุกใบของการขาย)
  ต้นฉบับกับสำเนาเลขเดียวกันนับเป็นใบเดียว แบบฟอร์มเปล่า: `แบบฟอร์มเปล่า_<ประเภท>` หรือ `แบบฟอร์มเปล่า_<n> ชนิด`
- **ทำความสะอาด**: `\ / : * ? " < > | ~` อักษรควบคุม และอักษรล่องหน (U+00AD, U+200B–200F, U+202A–202E, U+2060–2064, U+FEFF) เป็นช่องว่าง รวมช่องว่างซ้ำ ตัดช่องว่างและจุดหัวท้ายแต่ละส่วน
  ไม่สร้าง `_` จากการทำความสะอาด ยาวเกิน 80 ตัวอักษร (ไม่นับ `.pdf`) ตัดส่วนที่ยาวที่สุด (ปกติคือคู่ค้า) ตรงท้ายคำ
- **test**: กรรมการทั้ง 3 ไม่อ่านชื่อหน้าต่าง เฉลยเดิมจึงไม่เปลี่ยน S220–S221 แทน `window.print` ด้วยตัวจดชื่อหน้าต่าง (ส่ง `beforeprint`/`afterprint` เหมือนเบราว์เซอร์) แล้วกดพิมพ์จากหน้าจอ

ข้อความใหม่ (ส่วนของชื่อไฟล์ ไม่ขึ้นบนหน้าจอ เจ้าของโปรเจกต์อนุมัติทั้งหมด 2026-10-26): "ร่าง" (แทนเลขที่), "ยกเลิก" (ท้ายชื่อ), "ทุกคน", "<n> ใบ", "<n> ชนิด" (แบบฟอร์มเปล่าหลายชนิด), "รายการ" นำหน้าชื่อรายการเอกสาร

ตรวจในเบราว์เซอร์จริงแล้ว (2026-10-26, เครื่องของเจ้าของโปรเจกต์ `npm run dev` ร้าน demo-biz, เบราว์เซอร์ในแอป Claude แทน `window.print` แบบเดียวกับ S220):
ใบกำกับภาษี ใบวางบิล "หจก. บางมดขนส่ง" ใบแบบย่อลูกค้าหน้าร้าน ใบที่ยกเลิก ใบเสนอราคา รายงานภาษี ได้ชื่อตรงทั้ง 6 และชื่อแท็บกลับเป็นเดิมทุกครั้ง
ยังไม่ได้ดูชื่อในหน้าพิมพ์จริงของเบราว์เซอร์
ยังต้องตรวจด้วยมือ (container นี้เปิดหน้าพิมพ์จริงไม่ได้): บันทึกเป็น PDF จาก Chrome และ Edge บน Windows, Safari บน Mac และ iPad, Chrome บน Android
ด้วยใบวางบิลของ "หจก. บางมดขนส่ง" (ชื่อมีจุด) และใบที่ชื่อลูกค้ายาว ดูว่าชื่อไฟล์ที่เสนอตรงกับที่ตั้ง ภาษาไทยไม่เพี้ยน และชื่อแท็บกลับเป็นเดิมหลังปิดหน้าพิมพ์
(Safari และมือถือบางรุ่นอาจไม่ใช้ชื่อหน้าต่างเป็นชื่อไฟล์ ถ้าเป็นเช่นนั้นจดไว้ ไม่มีทางแก้จากหน้าเว็บนอกจากสร้าง PDF เองซึ่งเจ้าของเลือกไม่ทำ)
